# Подсказки: Vault: секреты и жизненный цикл доступа

[Вернуться к заданиям](practice.md)

Открывай следующий пункт только после собственной попытки.

1. Для KV v2 policy использует secret/data/housing, а CLI — secret/housing. Это ожидаемое различие.
2. Root token для настройки и application token для чтения — разные роли. Если отрицательная проверка прошла, сначала убедись, каким token ты пользуешься.
3. `hvac.exceptions.Forbidden` означает 403; `requests.exceptions.Timeout` означает истечение времени ожидания. `classify_error` получает эти исходы уже как status/timeout, без сетевого вызова.
4. Сократи вывод до «поле найдено / доступ запрещён». Печать всего JSON раскрывает значение.
5. Dev Vault не сохраняет данные после restart. Это свойство стенда, а не ошибка политики.

## Самопроверка

Как приложение получает первый token? Можно ли продлевать non-renewable token? Почему Kubernetes Secret не заменяет управление жизненным циклом доступа? Что происходит при отзыве уже закешированного секрета?

SDK KV v2 не принимает `secret/data/housing` как логический path: mount и имя секрета передаются раздельно. Для lifecycle найди `renew_self`/`revoke_self`, затем выбери только TTL/renewable из auth-метаданных. Не возвращай целый auth, даже если тестовый token одноразовый. SDK-тест с transport double не доказывает доступ к живому Vault; отрицательная live-проверка должна дать 403 ограниченному token.
