# Интеграция Vault: разбор архитектуры

## Зачем проследить начальное доверие

Если модель публична и уже включена в image, дополнительный запрос к Vault не улучшает поставку. Если загрузка закрыта ключом, нужно определить, откуда Pod получает первое удостоверение, кто обновляет доступ и что происходит при отказе. Здесь разбирается архитектура, а не разворачивается новый auth-стенд.

Исходные знания — Pod/readiness из Kubernetes и ограниченная policy/TTL из заданий 01–02. Собственный bundle остаётся тем же. Термины и роли описаны в [интеграции с Pod](../../README.md#интеграция-с-pod-и-ответственность-приложения) и [различии TTL и ротации](../../README.md#ttl-продление-отзыв-и-ротация).

## Контракт взаимодействия

На входе — JWT service account и имя согласованной role; после проверки Vault выдаёт token с policy и TTL. Следующий GET возвращает KV v2 payload, из которого загрузчик берёт ключ для конкретного артефакта. На выходе — проверенный bundle и готовый API, либо контролируемый отказ новой загрузки. Например, при timeout допустима ограниченная повторная попытка, при 403 нужно восстановить авторизацию; переименование очередного retry прав не добавит. Уже загруженная модель может работать без нового скачивания, поэтому readiness зависит от фактической потребности в секрете.

## Разбор сценария

Для публичного housing bundle Vault не нужен. Для private artifact пример потока: Pod service account housing-api в namespace housing → Kubernetes auth role housing-read → policy read secret/data/housing → короткий application token → загрузка artifact. JWT служит исходным удостоверением; root token остаётся только в локальной настройке.

При TTL60s приложение обновляет доступ заранее; при истечении и недоступности renewal прекращает новые загрузки и показывает unready, не выдавая секрет в лог. Ротация KV не меняет уже загруженное значение автоматически: нужен reload/restart по выбранному механизму. KV хранит статические значения; это не генератор динамических DB credentials.

Практический разбор: если сеть отвечает timeout, допускается ограниченный retry с backoff; если Vault отвечает 403, проверь policy/TTL/auth role. Сам retry не восстанавливает права. Agent может обновлять token и рендерить файл, приложение отвечает за reload файла. Здесь нет теста заполненных строк и не требуется писать design.md.
