# 14. Elasticsearch и OpenSearch: сравнение поиска

[Программа](../../README.md) · [Практика](practice.md) · [Подсказки](hints.md)

## Цель и вход

Выполнить keyword и vector search в двух движках на одинаковом корпусе. Нужны практика Qdrant, HTTP и qrels. Elasticsearch и OpenSearch изучаются отдельно: схожие названия полей не означают полную совместимость API.

## Документный индекс и keyword search

Текстовый индекс разбивает документы анализатором на токены. BM25 ранжирует совпадения с учётом частот и длины документа. Keyword search хорошо работает с точными терминами, кодами ошибок и именами конфигураций. Синонимы и смысловые перефразировки могут не совпасть лексически.

Embedding search ищет в пространстве модели и может находить перефразировки, но проигрывать на точных ID. Поэтому hybrid search сочетает сигналы, а не объявляет один метод универсально лучшим.

## Mapping и ingest

Elasticsearch использует dense_vector, OpenSearch — knn_vector с параметрами индекса и engine. В starter лежат два mapping-файла для ручных 4D-векторов. Включение ANN и способ запроса различаются. Не отправляй Elasticsearch JSON в OpenSearch, исправляя ошибки случайными удалениями полей.

Схема индекса задаётся до загрузки. Для изменения несовместимой размерности обычно создают новый индекс и переиндексируют данные. Стабильный document ID делает повторный ingest предсказуемым. Bulk API использует NDJSON: строка действия и строка документа, включая завершающий перевод строки. HTTP 200 у bulk не означает отсутствие ошибок по отдельным items; проверяй поле errors и результаты каждого действия.

## Сходство и гибридное ранжирование

Сырые scores BM25 и cosine нельзя бездумно складывать: масштабы и распределения различаются. Один простой прозрачный baseline — reciprocal rank fusion. Для документа суммируются `1/(c + rank)` по выдачам, где он присутствует; в упражнении фиксируется c=60. Это учебная реализация на клиенте, не зависящая от доступности платной server-side функции.

Пример: документ на 1-м месте в lexical и на 3-м в vector получает `1/61 + 1/63`. Фиксируй candidate pool и одинаковое k, иначе сравниваешь не только ранжирование, но и объём рассмотренных кандидатов.

## Эксплуатационные различия

Движки JVM требуют памяти сверх heap: остаются native allocations и filesystem cache. Xmx=768m не означает потребление всего контейнера 768 МБ. `vm.max_map_count` относится к Linux VM; изменение параметра на macOS не настраивает автоматически нужную VM.

В учебных стендах security отключена и порты привязаны к loopback. Это даёт локальный бесплатный API, но не описывает production-аутентификацию, TLS и разграничение доступа. Не используй cloud-only semantic endpoints для обязательной практики: embeddings передаются явно.

На одинаковых данных сравни качество, ingest time, latency и расход памяти. Восемь документов проверяют API, но не позволяют делать вывод о масштабировании. Для производительности увеличь корпус и укажи железо, число запросов и прогрев. Отличай собственные измерения от документации производителя.
