# Подсказки: Elasticsearch и OpenSearch: сравнение поиска

[Вернуться к заданиям](practice.md)

Открывай следующий пункт только после собственной попытки.

1. Bulk требует Content-Type application/x-ndjson и последнюю пустую строку. Статус HTTP — только первый уровень проверки.
2. В OpenSearch vector field использует dimension, в Elasticsearch — dims. Запросы тоже различаются.
3. Повторная загрузка с новым случайным ID увеличивает индекс; используй corpus ID как _id.
4. RRF складывает ранги, а не scores. Начни с ручного примера из двух коротких списков.
5. Не меняй query embeddings между движками: тогда сравнение теряет смысл.

6. В SDK есть indices.exists/create/get_mapping/get_settings, bulk, indices.refresh и search. Перед созданием разбери mapping, перед повторным использованием сверь векторную схему. Не удаляй чужой индекс ради совместимости.
7. ES 8 response может быть ObjectApiResponse: получай items через response["items"]. В обоих SDK HTTP 200 bulk ещё не успех. Исключение частичного отказа должно содержать IDs.
8. Нормализуй _id в int один раз при разборе hits, иначе строка "7" не совпадёт с qrels ID7. Ранги lexical/vector, а не сырые scores, поступают в RRF.
9. Записывающий тест включается двумя флагами и -m writes; он требует реализации метрик/RRF, создаёт собственное имя и не использует заранее загруженный course-docs.
