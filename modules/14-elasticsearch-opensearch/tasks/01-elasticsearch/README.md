# Elasticsearch: bulk и ошибки

[Теория](../../README.md) · [Практика модуля](../../practice.md) · [Подсказки](../../hints.md)

## С чего начать

Реализуй `build_bulk(documents, index) -> str`: NDJSON action/document с завершающим переводом строки, устойчивым _id и полями text/topic/vector; повторный вызов даёт те же IDs. Пустое имя индекса и повтор ID в одном корпусе — ValueError. `bulk_failures(response) -> list[str]` возвращает IDs операций со status >= 300 либо error, даже если HTTP был 200. Реальные запросы выполняй отдельно после этих проверок; mapping.json лежит рядом.

Подготовь [основное окружение](../../../../SETUP.md). Все команды ниже выполняются из корня курса. Платформа задания: **cpu**. Функции и ожидаемые результаты описаны также в `test_task.py`; тесты используют небольшие фиксированные данные.

## Исходное задание

Напиши ingest-скрипт из corpus.json: стабильные IDs, NDJSON bulk, проверка items. Реализуй match-запрос и knn-запрос для одного query vector. Сохрани top-5, scores и время. Повторный ingest не меняет число документов.

## Проверка

```bash
make task TASK=14-elasticsearch-opensearch/01-elasticsearch
```

У этой задачи проверяются функции: запускай их тестами, отдельного CLI нет.

До реализации функции ожидается `NotImplementedError`. Реализуй заготовку, сохраняя контракт функций из тестов. Офлайн-тест не подтверждает действия на внешнем стенде: проверки, требующие работающего сервиса, включаются явно через `MLOPS_RUN_INTEGRATION=1`.

## Результат

Функции должны проходить проверки положительных и отрицательных случаев. Для собственного эксперимента сохраняй исходные измерения в `work/`: они пригодятся для повторного сравнения. Отдельное письменное резюме не требуется. После работы останови стенд по инструкции practice.md.

### Реальная проверка уже загруженного индекса

```bash
MLOPS_RUN_INTEGRATION=1 ELASTICSEARCH_URL=http://127.0.0.1:9200 make task TASK=14-elasticsearch-opensearch/01-elasticsearch
```

Probe читает count и выполняет поисковые запросы без изменения индекса. Для общего корпуса ожидаются count=8, kNN IDs 7/8 и документ 7 по слову Vault. Это ожидаемые инварианты, не пример реально измеренной latency. До запуска самостоятельно загрузи индекс с mapping из задания. Без opt-in probe пропускается; с opt-in отсутствие URL, сервера или индекса — ошибка.
