# Мониторинг: качество и drift

Зависит от собственной модели и фиксированной выборки housing; не нужен дополнительный SDK.

## Что редактировать

Реализуй предметные TODO в `solution.py`: входы и ожидаемые результаты перечислены ниже в разделе «Контракт и проверка» и в `test_task.py`. После практического опыта заполни `report.json` собственными наблюдениями по `report.template.json`.

Готовый `grading.py` проверяет согласованность отчёта; писать свой валидатор не требуется. `scenario.json` содержит синтетический пример для тестов и не подтверждает выполнение практики. Сдавай свои измерения и команды, сохраняя ожидаемое поведение тестов.

## Подготовка и выполнение

Команды запускаются из корня репозитория. Общая установка — [SETUP](../../../../SETUP.md). Окружение CPU с pytest; SDK/CLI устанавливаются отдельно по SETUP и не нужны для сбора тестов. NumPy допустим; данные не скачиваются при импорте.

На фиксированных 500 строках сохрани row ID, target и prediction; вычисли MAE. Создай отдельную копию признаков, сдвинь MedInc на контролируемую величину (например +2), сравни q10/q50/q90 с reference, повтори predict и анализ ошибок. Сохрани оригинальную выборку неизменной. scenario.json малый для точной самопроверки; report.template.json замени реальными 500 наблюдениями. Вручную объясни data drift vs concept drift, почему без свежих labels MAE недоступна и почему сдвиг не доказывает падение качества. Housing labels здесь присоединяются с задержкой из известной выборки, это не online ground truth.

Проверка выбранного задания:

```bash
make task TASK=09-monitoring/03-quality-drift
python scripts/run_task.py run 09-monitoring/03-quality-drift -- --report modules/09-monitoring/tasks/03-quality-drift/report.json
```

CLI читает JSON --report и печатает наблюдения. Содержательную схему проверяет pytest через готовый grading.py; --collect включает TODO автоматизации сбора.

## Контракт и проверка

`analyze(targets, predictions, reference_medinc, shifted_medinc) -> dict` возвращает mae по JOIN уникального id, reference_quantiles и shifted_quantiles для q=[0.1,0.5,0.9] с линейной интерполяцией, median_shift=shifted_median-reference_median. Требуй одинаковые непустые наборы id, конечные числа, непустые признаки. Дубликаты/missing ID/NaN — ValueError. `validate_report(report)` делегирует analyze по четырём полям fixture.

Схема JSON задаётся `report.template.json`; null нужно заменить измерениями. Возвращаемые значения и отрицательные примеры зафиксированы в `test_task.py`. Отсутствующие поля, несовместимые типы и противоречивые наблюдения должны приводить к `ValueError`. До реализации тесты **RED**: незаполненный report.json вызывает ValueError; предметная заготовка выбрасывает `NotImplementedError`; это ожидаемый незавершённый код, а не успешный тест.

Офлайн-проверки проверяют числа, переходы состояний и согласованность наблюдений. Они не доказывают реальный запуск стенда. Вручную предъяви команды, время, обезличенные ответы и объяснение причин; совпадение схемы без реальных наблюдений не закрывает практику. Тесты не разворачивают и не удаляют ресурсы. Любые добавленные live-проверки разрешены только с `MLOPS_RUN_INTEGRATION=1`, читают уже работающий стенд и не меняют его.
