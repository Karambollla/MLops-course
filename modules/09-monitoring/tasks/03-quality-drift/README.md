# Качество и drift

## Что предстоит сделать

API может быстро возвращать HTTP 200 и при этом давать неточные прогнозы. Нужно дождаться известных правильных ответов и связать каждый из них с прежним прогнозом. Порядок доставки не гарантирован, поэтому соединяем по ID. Отдельно сравниваем состав входов: он может измениться даже без ухудшения ошибки модели.

Ты реализуешь один расчёт с двумя результатами: MAE по связанным target/prediction и описание изменения признака MedInc. Для классификатора вместо MAE сравнивались бы предсказанные и истинные классы. Одних HTTP-кодов также было бы недостаточно.

В [scenario.json](scenario.json) уже есть небольшие числовые выборки. Сервер для этой части не требуется. Редактируй `analyze` в [solution.py](solution.py). Перед началом прочти [качество и drift](../../README.md#три-уровня-здоровья-и-качество-модели), где разобраны MAE, квантили и границы выводов.

## Аргументы `analyze`

Точная сигнатура из заготовки:

```python
def analyze(targets, predictions, reference_medinc, shifted_medinc):
    ...
```

| Аргумент | Тип и формат | Откуда берётся и зачем нужен | Пример |
|---|---|---|---|
| `targets` | Непустой список dict с `id` и конечным числовым `target` | Из scenario либо поздней разметки. Истинные ответы для измерения качества | `[{"id": "a", "target": 1}, {"id": "b", "target": 3}]` |
| `predictions` | Непустой список dict с `id` и конечным числовым `prediction` | Из scenario либо результатов модели для тех же объектов. Порядок может отличаться от targets | `[{"id": "b", "prediction": 3}, {"id": "a", "prediction": 2}]` |
| `reference_medinc` | Непустая одномерная числовая выборка без NaN/Infinity | Значения признака MedInc в выбранном эталонном окне | `[1, 5]` |
| `shifted_medinc` | Такая же выборка текущего окна. Длина не обязана совпадать с reference | Значения того же признака в сравниваемом потоке | `[3, 7]` |

ID — устойчивый идентификатор строки, не позиция в списке. Внутри каждого списка ID уникальны, а множества ID обеих сторон должны совпадать полностью. MedInc — признак дохода района в California Housing. Его выборки не являются targets и не соединяются по ID. В `scenario.json` лежат все четыре аргумента под одноимёнными ключами. Тест читает файл и передаёт эти значения функции, сама `analyze` файл не открывает.

Для примера из таблицы форма результата:

```python
{
    "mae": 0.5,
    "reference_quantiles": [1.4, 3.0, 4.6],
    "shifted_quantiles": [3.4, 5.0, 6.6],
    "median_shift": 2.0,
}
```

`mae` — средняя абсолютная ошибка после join. `reference_quantiles` и `shifted_quantiles` содержат q=0.1, 0.5, 0.9 именно в этом порядке. `median_shift` может быть отрицательным и равен текущей медиане минус эталонная. Для выборки из одного числа все три квантиля равны этому числу. При плохих числах, пустых выборках, дубликатах и несовпадении ID вызывай `ValueError`. Частичный inner join не подходит: он скрывает потерянные наблюдения.

## Реализация и проверка

Реализуй `analyze` в `solution.py` по контракту выше. Для проверки достаточно основного Python-окружения. Сервер, Docker и обученный bundle не нужны:

```bash
make task TASK=09-monitoring/03-quality-drift
```

У `solution.py` нет CLI. Чтобы проверить заготовленный scenario вручную, из корня курса выполни в Python:

```python
import json
import runpy
from pathlib import Path

analyze = runpy.run_path(
    "modules/09-monitoring/tasks/03-quality-drift/solution.py",
)["analyze"]
scenario = json.loads(Path(
    "modules/09-monitoring/tasks/03-quality-drift/scenario.json",
).read_text())
print(analyze(**scenario))
```

Ожидаются MAE `2/3`, квантили `[1.4, 3, 4.6]` и `[3.4, 5, 6.6]`, `median_shift=2`. Поменяй порядок прогнозов во входном списке: результат должен сохраниться. Для медианного сдвига используется текущая медиана минус эталонная, поэтому он может быть отрицательным.

Функция не назначает порог alert и не доказывает ухудшение настоящей модели на этих вымышленных данных. Изменение признака само по себе не устанавливает причину изменения MAE. Для новой оценки нужны реальные target/prediction с сопоставимыми ID. Очистка сервера здесь не требуется: расчёт выполняется в памяти.
