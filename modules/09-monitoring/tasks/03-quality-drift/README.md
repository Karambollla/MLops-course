# Качество и drift

## Зачем соединять прогнозы с ответами

Метрики HTTP не знают, насколько верен прогноз. Истинная стоимость может поступить позже и в другом порядке. Здесь ID связывает конкретный прогноз с target, а два массива MedInc позволяют отдельно измерить изменение состава входов.

В `scenario.json` уже есть небольшие числовые выборки; сервер для этой части не требуется. Ты реализуешь `analyze` в `solution.py`. Перед началом прочти [качество и drift](../../README.md#три-уровня-здоровья-и-качество-модели), где разобраны MAE, квантили и границы выводов.

## Формат входа и выхода

`targets` — записи `{"id": ..., "target": число}`, `predictions` — `{"id": ..., "prediction": число}`. В двух других аргументах — непустые числовые выборки признака MedInc. Например, target `a=1,b=3` и predictions в порядке `b=3,a=2` дают MAE=.5: соединение по позиции дало бы другую ошибку. Возвращаются MAE, три линейно интерполированных квантиля каждой выборки и разность медиан. Пустой/неоднозначный join должен отклоняться, потому что средняя по случайно совпавшей части скрыла бы пропущенные ответы. Статистический сдвиг признака не подменяет измерение ошибки по target.

## Реализация и проверка

Реализуй `analyze(targets, predictions, reference_medinc, shifted_medinc)` в `solution.py`. Объедини target и prediction по ID независимо от порядка. Верни `mae`, `reference_quantiles`, `shifted_quantiles` (q=.1,.5,.9 с линейной интерполяцией), `median_shift` (shifted median минус reference median). При несовпавших множествах ID, дубликатах, пустых выборках и нечисловых/нефинитных значениях — ValueError.

```bash
make task TASK=09-monitoring/03-quality-drift
```

Вход `scenario.json` оставлен для расчётов: MAE=2/3; квантили [1.4,3,4.6] и [3.4,5,6.6]; median_shift=2. Дополнительно примени функцию к собственным prediction/target данным с ID и двум выборкам MedInc. Drift признака сам по себе не доказывает ухудшение MAE: для MAE нужны размеченные targets.
