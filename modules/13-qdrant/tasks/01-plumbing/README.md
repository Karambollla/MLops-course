# Qdrant: загрузка и фильтрация

[Модуль и подготовка](../../README.md#подготовка-к-заданиям) · [Все задания модуля](../../README.md#задания) · [Окружение курса](../../../../SETUP.md)

## Зачем нужна загрузка с устойчивыми IDs

Поисковый сервис должен получать те же документы после повторного импорта, а не новую копию каждого. Здесь ты соединяешь JSON-корпус с Qdrant и проверяешь фильтрацию по теме. Как устроены point, payload и upsert, объясняется в [пути данных](../../README.md#коллекция-и-путь-данных), а место фильтра — в [разборе запроса](../../README.md#запрос-и-фильтрация).

Изменяй только учебные функции в соседнем [solution.py](solution.py): `main()` уже читает CLI-аргументы. Предоставлены `labs/search/corpus.json` с восемью ручными 4D-векторами, `queries.json` и Compose Qdrant 1.13.6. В корпусе ID 7 — политика Vault, ID 8 — срок жизни credentials. Запрос `security` заранее размечен как подходящий обоим. Подготовь [отдельное окружение Qdrant и CPU-стенд](../../README.md#подготовка-к-заданиям). Языковая embedding-модель не нужна.

## Шаг 1. Преобразовать документы в points

### `build_points(documents: list[dict]) -> list[dict]`

| Параметр | Тип | Формат и смысл | Откуда взять | Пример |
|---|---|---|---|---|
| `documents` | `list[dict]` | Документы с `id`, `text`, `topic`, `vector`. Один элемент — один point | Декодированный `labs/search/corpus.json` или маленький список для теста | `[{"id":7,"text":"Vault policy","topic":"security","vector":[0,1]}]` |

Результат для примера:

```python
[{"id": 7, "vector": [0, 1], "payload": {"text": "Vault policy", "topic": "security"}}]
```

`payload` — поля для показа текста и фильтрации. Вектор не нужно дублировать в payload. Сохрани связь исходного ID с его текстом и вектором. IDs должны быть уникальными неотрицательными `int` без `bool`. Векторы должны содержать конечные числа, иметь одинаковую непустую размерность и ненулевую норму. Неверный ID, повтор ID или неправильная геометрия вызывают `ValueError`. В маленьком примере взят один документ с ID 7 и двумя условными координатами: он показывает форму преобразования, а не вектор серверного корпуса. Серверный корпус этого задания имеет четыре координаты.

## Шаг 2. Создать коллекцию и загрузить корпус

### `index_documents(url: str, corpus_path: Path, collection: str = "course-docs") -> None`

| Параметр | Тип | Формат и смысл | Откуда взять | Пример |
|---|---|---|---|---|
| `url` | `str` | HTTP-адрес Qdrant, включая схему и порт | Запущенный Compose, CLI `--url` | `"http://127.0.0.1:6333"` |
| `corpus_path` | `pathlib.Path` | Путь к JSON-массиву документов, а не само содержимое файла | CLI `--corpus` | `Path("labs/search/corpus.json")` |
| `collection` | `str` | Имя коллекции для создания или повторного использования | CLI `--collection` или уникальное имя теста | `"course-docs"` |

Прочитай корпус, проверь его через `build_points` и используй настоящий `QdrantClient`: создание коллекции с `size=4`, `Distance.COSINE`, затем upsert. Повторный импорт исходных восьми IDs должен оставить восемь points. Для существующей несовместимой схемы нужен `ValueError` до записи с сохранением прежних данных. Не удаляй коллекцию ради изменения размерности. Во всех SDK-вызовах используй переданное имя `collection`.

Функция возвращает `None` и меняет состояние коллекции. Ошибки чтения файла и подключения нельзя выдавать за успешную загрузку. При отсутствующем SDK заготовка поднимает `RuntimeError` с командой установки.

## Шаг 3. Получить ранжированные документы

### `query_documents(url: str, vector: list[float], k: int = 2, topic: str | None = None, collection: str = "course-docs", dimension: int = 4) -> list[dict]`

| Параметр | Тип | Формат и смысл | Откуда взять | Пример |
|---|---|---|---|---|
| `url` | `str` | HTTP-адрес сервера | Тот же адрес, что при загрузке | `"http://127.0.0.1:6333"` |
| `vector` | `list[float]` | Конечный ненулевой вектор длины `dimension` | Поле `vector` запроса из `queries.json`, CLI `--vector` | `[0,0,0,1]` |
| `k` | `int` | Положительный максимум hits, без `bool` | CLI `--k` | `2` |
| `topic` | `str` или `None` | Точное значение payload-фильтра. `None` отключает фильтр | Категория корпуса, CLI `--topic` | `"security"` |
| `collection` | `str` | Имя уже загруженной коллекции | Параметр загрузки или CLI `--collection` | `"course-docs"` |
| `dimension` | `int` | Положительная размерность без `bool`, должна соответствовать коллекции | Версия схемы индекса, CLI `--dimension` | `4` |

Вызови `query_points(..., with_payload=True)`, прочитай список `.points` и верни hits в порядке ответа Qdrant. Каждый hit имеет форму `{"id":7,"score":1.0,"payload":{"text":"...","topic":"security"}}`. Текст берётся из payload сервера. Для security-вектора ожидаются IDs 7 и 8 со scores примерно 1.0 и 0.9847. Нельзя находить соседей самостоятельно по исходному JSON вместо SDK-запроса.

При `topic` используй `Filter`, `FieldCondition`, `MatchValue` в `query_filter`, до выбора top-k. Неизвестный topic возвращает `[]`, как и отсутствие любых hits. Неверные `k`, `dimension`, длина, конечность или норма вектора вызывают `ValueError` до запроса. Закрой созданный функцией клиент после работы.

## Готовый CLI

`main()` уже разбирает аргументы и вызывает твои функции. Его не нужно реализовывать заново.

| Аргумент | Формат и назначение | По умолчанию |
|---|---|---|
| `--action` | `index` загружает корпус, `query` печатает JSON-список hits | `index` |
| `--url` | HTTP-адрес сервера | `http://127.0.0.1:6333` |
| `--corpus` | Путь к JSON-массиву документов, используется при `index` | `labs/search/corpus.json` |
| `--collection` | Имя коллекции для обеих операций | `course-docs` |
| `--vector` | Координаты через пробел, используется при `query` | `0 0 0 1` |
| `--k` | Максимум результатов поиска | `2` |
| `--topic` | Точная категория, необязательно | Без фильтра |
| `--dimension` | Ожидаемая длина вектора запроса | `4` |

Запуск `index` ничего не печатает при успехе, поскольку функция возвращает `None`. Запуск `query` выводит JSON со списком результатов. Успешное завершение процесса и число points проверяются отдельно.

## Проверка без внешнего сервера

Из корня курса:

```bash
make task TASK=13-qdrant/01-plumbing
MLOPS_RUN_SDK=1 python scripts/run_task.py test 13-qdrant/01-plumbing -- -m sdk
```

Первый запуск проверяет преобразование и ошибки входа. Второй требует окружения Qdrant из главы и использует настоящий `qdrant-client==1.13.3` в памяти процесса: дважды вызывает загрузчик, читает count, vectors и payload, затем проверяет твой поиск по именованной коллекции, фильтр и неверную размерность. В cosine-коллекции SDK хранит нормализованные векторы, поэтому они сравниваются с нормализованным исходным JSON. Без флага SDK-проверка пропускается. Незаполненные функции дают `NotImplementedError`.

## Проверка на сервере

Запусти Compose по [подготовке](../../README.md#подготовка-к-заданиям), затем выполни свою реализацию:

```bash
python modules/13-qdrant/tasks/01-plumbing/solution.py --corpus labs/search/corpus.json
python modules/13-qdrant/tasks/01-plumbing/solution.py --corpus labs/search/corpus.json
python modules/13-qdrant/tasks/01-plumbing/solution.py --action query --vector 0 0 0 1 --topic security
```

Два импорта сохраняют восемь points. Запрос печатает hits с IDs 7/8, текстом и topic из payload. Score около 1.0 для Vault и 0.9847 для credentials получается из [геометрии корпуса](../../README.md#от-текста-к-embedding-и-расстоянию), а не из уверенности модели. Вызов `query_documents` с `[1,0]` должен дать `ValueError` до сети.

Проверка уже загруженного `course-docs`:

```bash
MLOPS_RUN_INTEGRATION=1 QDRANT_URL=http://127.0.0.1:6333 python scripts/run_task.py test 13-qdrant/01-plumbing -- -m 'integration and not writes'
```

Она читает count и payload прямым HTTP и проверяет HTTP 400 для неверной размерности. Чтобы проверить именно свои функции, сначала реализуй `ranking_metrics` в задании 02, затем запусти:

```bash
MLOPS_RUN_INTEGRATION=1 MLOPS_RUN_WRITES=1 QDRANT_URL=http://127.0.0.1:6333 python scripts/run_task.py test 13-qdrant/01-plumbing -- -m writes
```

Этот тест выбирает новое UUID-имя коллекции, дважды вызывает твою `index_documents`, получает все четыре выдачи через `query_documents` и передаёт их IDs в твою `ranking_metrics`. На ручном корпусе при k=2 ожидаются recall=precision=mrr=1. Также проверяются security и неизвестный topic. После теста удаляется только его коллекция. Для записи нужны оба флага. При включении недоступный SDK/сервер или незавершённая реализация дают ошибку.
