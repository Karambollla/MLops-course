# Recall, precision и MRR

[Теория](../../README.md) · [Практика модуля](../../practice.md) · [Подсказки](../../hints.md)

## С чего начать

Реализуй `ranking_metrics(retrieved, relevant, k) -> dict` с ключами recall, precision, mrr. Берутся первые k позиций исходной выдачи: дубликат ID не увеличивает число попаданий, MRR учитывает исходную позицию первого попадания. Precision делится на k. Для пустой разметки все три значения равны 0; такие запросы в реальном benchmark лучше учитывать отдельно. k — положительное целое, bool не допускается.

Подготовь [основное окружение](../../../../SETUP.md). Все команды ниже выполняются из корня курса. Платформа задания: **cpu**. Функции и ожидаемые результаты описаны также в `test_task.py`; тесты используют небольшие фиксированные данные.

## Исходное задание

Реализуй Recall@2 и MRR. Для ручных векторов ожидается Recall@2=1 на четырёх учебных запросах; это проверка wiring, а не доказательство семантического качества. Отдельно проверь метрику на выдаче [1,3] при relevant [1,2]: Recall@2=0,5.


У этой задачи проверяются функции: запускай их тестами, отдельного CLI нет.

До реализации функции ожидается `NotImplementedError`; для отчётов — ошибка незаполненного поля. Исправляй заготовку или собственный результат, сохраняя ожидаемое поведение тестов. Офлайн-тест не подтверждает действия на внешнем стенде: проверки, требующие работающего сервиса, включаются явно через `MLOPS_RUN_INTEGRATION=1`.
