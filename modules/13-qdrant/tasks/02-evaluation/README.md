# Recall, precision и MRR

## Зачем считать метрики отдельно от поиска

HTTP 200 и два документа в ответе не говорят, подходят ли они пользователю. Нужна функция, которая сравнивает ранжированные IDs с независимыми qrels. [Разбор метрик](../../README.md#качество-выдачи-и-разобранные-метрики) показывает, откуда берутся числители, знаменатели и позиции.

Предоставлены `solution.py`, фиксированные тесты и `labs/search/queries.json`. Для функции не нужны Qdrant и embedding-модель: вход — два списка IDs и k, выход — три числа. Это CPU-задача в [основном окружении](../../../../SETUP.md). Полученную функцию затем можно использовать для выдачи первого задания.

## Технический контракт

Реализуй `ranking_metrics(retrieved, relevant, k) -> dict[str,float]` с ключами `recall`, `precision`, `mrr`.

Рассматриваются первые k позиций исходной выдачи. Один ID увеличивает число попаданий только один раз. Recall делится на число уникальных relevant IDs, precision — на k даже при короткой выдаче. `mrr` здесь означает reciprocal rank одного запроса: обратную исходную позицию первого релевантного результата в top-k. Среднее по нескольким запросам вычисляется уже снаружи. Для пустой разметки или отсутствия попаданий соответствующие значения нулевые. k — положительное целое без bool; неверное k вызывает ValueError.

Не удаляй дубликаты до отсечения top-k. Для `[1,1,2]`, relevant `[1,2]`, k=2 третья позиция не рассматривается: recall=0.5, precision=0.5, mrr=1.0. Для `[9,2]` с той же разметкой — recall=0.5, precision=0.5, mrr=0.5. Пустая выдача даёт три нуля. Это примеры контракта, не готовый алгоритм.

## Проверка и применение

```bash
make task TASK=13-qdrant/02-evaluation
```

CLI отсутствует; тесты вызывают функцию напрямую. Пока она не реализована, ожидается NotImplementedError. После unit-проверки подай выдачи первого задания и relevant из `queries.json`. На четырёх ручных запросах ожидается Recall@2=1 по построению данных. Это проверка соединения компонентов; [ANN recall и смысловая релевантность](../../README.md#exact-и-approximate-search) проверяют разные свойства.

Для эксперимента усредняй метрики по одним и тем же запросам и сохраняй исходные IDs, k и qrels. Не меняй разметку ради улучшения числа. Функция не управляет стендом: если Qdrant был запущен отдельно, останови его по практике модуля. Письменная сдача не нужна.

Integration/writes тест первого задания уже соединяет эти шаги: он создаёт уникальную коллекцию через твою index_documents, получает query_documents по всем queries и передаёт фактические IDs в твою ranking_metrics. Для запуска нужны оба флага MLOPS_RUN_INTEGRATION=1/MLOPS_RUN_WRITES=1 и завершённое первое задание; команда находится в его README. Локальные unit-тесты метрик по-прежнему не требуют SDK.
