# Подсказки: Qdrant и основы векторного поиска

[Вернуться к заданиям](practice.md)

Открывай следующий пункт только после собственной попытки.

1. Для Qdrant client выбранной версии используй query_points(...).points; старые примеры search могут отличаться.
2. Payload содержит текст и topic; вектор не надо дублировать в payload для фильтрации.
3. Обрабатывай relevant IDs как множество. Дубликат в выдаче не должен дважды увеличивать число попаданий.
4. В toy corpus первые две координаты не связаны с реальным языком. Не переносить эти выводы на полноценную embedding-модель.
5. Если настоящая модель требует query prefix по model card, применяй его одинаково во всех сравниваемых движках.

6. query_points возвращает объект с .points. Бери id/score/payload из каждого point; не вычисляй список соседей по исходному JSON вместо запроса к SDK.
7. topic должен войти в query_filter до выбора top-k. При неизвестном topic ожидается [], а не выдача без фильтра.
8. Передавай collection явно в каждом вызове SDK: тест использует уникальное имя вместо course-docs. Старые вызовы index_documents(url,corpus_path) должны продолжать работать.
9. Подай int IDs из query_documents прямо в ranking_metrics вместе с relevant из queries.json. Без независимых qrels близость вектора не превращается в измерение релевантности.
