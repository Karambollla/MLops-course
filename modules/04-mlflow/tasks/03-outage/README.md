## Зачем сохранять незавершённую регистрацию

Обучение может завершиться успешно, а сервер реестра оказаться недоступным. Потерять связь с исходным run или автоматически повысить champion после такой ошибки опаснее, чем оставить результат ожидающим восстановления. Здесь проверяется переход `pending → registered` с сохранением происхождения. Граница локального состояния и внешнего побочного действия разобрана в [теории отказа регистрации](../../README.md#регистрация-после-сетевого-отказа).

## Что уже есть и что добавить

Из [Registry-темы](../02-registry/README.md) нужны существующий run ID, адрес его artifact и действующая версия champion. `pending` хранит эти значения и устойчивый run key. В offline-тестах callback подменяет сетевую регистрацию; на стенде он должен регистрировать тот же обученный результат, а не запускать обучение заново. Реализуй сохранение JSON и переход состояния; сам статус ошибки не является сигналом продвижения модели.

Например, до отказа champion=`"4"`, pending относится к `run-1`. Callback с `ConnectionError` оставляет pending на диске и champion 4. После восстановления callback возвращает `"8"`: новое состояние registered содержит version 8 и прежний run-1, но champion по-прежнему 4. Повтор уже зарегистрированного состояния не вызывает callback. Это подтверждает локальную идемпотентность; остановка сети после создания версии на сервере, но до ответа клиенту остаётся отдельным окном неопределённости.

## Где работать и контракт

Редактируй `modules/04-mlflow/tasks/03-outage/solution.py`. Дополнительные тесты размещай в этой же папке.

`recover_registration(pending: dict, register, local_path: Path) -> dict`: pending содержит run_key, run_id, artifact_uri, status="pending" и champion_version. callback register(pending) возвращает конкретный version (строка); вызывай только для pending. При ConnectionError атомарно сохрани исходную связь и status=pending в local_path, верни {status:"pending", run_id, run_key, artifact_uri, champion_version}; не продвигай champion. После восстановления сохрани status=registered и version с теми же исходными идентификаторами; уже registered повторно не вызывает callback и не меняет результат. Прочие ошибки не скрывай. Реальный опыт: останови MLflow, попробуй регистрацию, зафиксируй ошибку/локальную политику, подними сервер и восстанови регистрацию того же run. Проверь сохранённое состояние и отсутствие повторного продвижения champion. Offline callback не доказывает exactly-once при падении после remote side effect.

## Среда и зависимости

Базовая среда из SETUP: Python, pytest; CPU, Linux/macOS.

Зависит от 04-mlflow/02-registry. Реальный outage выполняй на учебном Compose, не удаляя volume. Ожидаемое поведение на стенде: исходный run и bundle доступны после восстановления, champion не поменялся из-за ошибки.

## Запуск и результат

Из корня репозитория:

```bash
make task TASK=04-mlflow/03-outage
```

Тесты функций работают offline на маленьких входах и временных файлах. До реализации ожидается `NotImplementedError`; ошибка импорта означает проблему подготовки среды. Проверка функций не заменяет описанный опыт на данных или стенде.

Это задание использует функции; импортируй заготовку через `course_tasks.load_task("04-mlflow/03-outage")` из Python. CLI не требуется.

## Требования практического опыта

Останови сервер и запусти регистрацию ещё раз. Зафиксируй ошибку и выбранную политику сохранения локальных результатов. Запусти сервер обратно и восстанови регистрацию без потери связи с исходным запуском. Не продвигай кандидата автоматически после ошибки.

## Приёмка и очистка

Запусти указанную выше команду `make task` после реализации и исправления ошибок. Проверяемые случаи перечислены в соседнем `test_task.py`.

После опыта останови стенд: `docker compose -f labs/mlflow/compose.yaml down`. Не удаляй volume без экспорта истории; артефакты `work/` сохрани для следующих модулей.

## Пример корректного результата

При ConnectionError состояние остаётся pending, исходный run_id сохраняется, champion не продвигается. Успешный повтор меняет status на registered и сохраняет точную version. Повтор уже registered не вызывает регистрацию снова.
