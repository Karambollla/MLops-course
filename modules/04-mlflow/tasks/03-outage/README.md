# Восстановить регистрацию после недоступности сервера

[Модуль](../../README.md) · [Подготовка среды](../../README.md#подготовка-к-заданиям) · [Все задания](../../README.md#задания)

## Исходная ситуация

Модель обучилась и сохранилась, но её регистрация не завершилась из-за сетевой ошибки. Действующий champion при этом менять не нужно. Требуется записать, какой именно результат ожидал регистрации, и после восстановления сервера продолжить с ним.

Второе задание связывало Pipeline с run и версией. Теперь проверяется сохранение этой связи при отказе. [Теория восстановления](../../README.md#регистрация-после-сетевого-отказа) объясняет состояния и границы повторного выполнения. Для ручного опыта нужны собственный исходный run, ссылка на уже сохранённую MLflow Model и существующий champion.

## Что реализовать

Редактируй [solution.py](solution.py). Функция отвечает за локальное состояние. Операция SDK передаётся ей отдельным вызываемым объектом, чтобы проверять сохранение независимо от причины сетевой недоступности. Такую переданную функцию называют callback: `recover_registration` вызывает её, когда нужно выполнить внешнюю регистрацию.

```python
def recover_registration(pending: dict, register, local_path: Path) -> dict:
    ...
```

| Аргумент | Тип и формат | Происхождение и назначение | Пример |
|---|---|---|---|
| `pending` | `dict` с исходным состоянием | Создаётся для подготовленной модели. При повторе читается из локального JSON. Допускается уже подтверждённое состояние | Объект ниже |
| `register` | Вызываемый объект с контрактом `register(payload) -> str` | Выполняет регистрацию исходного артефакта и возвращает номер версии строкой. При распознанной сетевой недоступности выбрасывает `ConnectionError` | Адаптер реального вызова SDK, в unit-тестах — подставная операция |
| `local_path` | `Path` к локальному JSON | Сохраняет состояние у клиента, независимо от серверного volume. Родительские папки могут отсутствовать | `Path("work/registration/pending.json")` |

## Как выглядит состояние

Предположим, приложение использует champion версии 4. Новая модель принадлежит обучению `run-7`, уже сохранена в MLflow, но её регистрация ещё не подтверждена:

```json
{
  "run_key": "key-1",
  "run_id": "run-7",
  "artifact_uri": "runs:/run-7/model",
  "status": "pending",
  "champion_version": "4"
}
```

| Поле | Смысл и источник |
|---|---|
| `run_key` | Устойчивый ключ этой операции. Сохраняется при повторных попытках |
| `run_id` | Исходное обучение, которое уже завершилось |
| `artifact_uri` | Ссылка на сохранённую MLflow Model. Возьми её из результата логирования модели |
| `status` | `pending` — регистрация не подтверждена. `registered` — известна зарегистрированная версия |
| `champion_version` | Номер действующей версии до попытки регистрации |
| `version` | Добавляется после успешной регистрации новой модели |

URI в примере показывает один поддерживаемый вид ссылки. SDK 3.1.1 может вернуть другой model URI. Сохраняй фактически возвращённую ссылку, не собирай её из предположений о внутреннем пути файлов.

## Поведение функции

1. Для `status="pending"` вызови `register` с исходными сведениями о модели.
2. Если получен `ConnectionError`, сохрани pending в `local_path` и верни его содержимое. Не изменяй переданный словарь и не теряй идентификаторы.
3. После успешного ответа, например `"8"`, сохрани и верни состояние `registered` с `version="8"`. Исходные `run_id`, `artifact_uri`, `run_key`, `champion_version` остаются прежними.
4. Для уже `registered` состояния верни прежний результат без нового вызова регистрации.
5. `ValueError` и другие неожиданные ошибки пробрасывай. Они не обозначают автоматически недоступную сеть.

Создай недостающие родительские каталоги. Записывай JSON через временный файл и замену готового результата. Читатель не должен увидеть частично записанную строку.

После успешной попытки пример выше будет иметь `status="registered"` и `version="8"`, а `champion_version` останется `"4"`. Регистрация нового результата и выбор действующего champion — разные действия.

## Подготовка настоящей операции регистрации

Передаваемый `register` использует SDK для регистрации `payload["artifact_uri"]` под нужным именем модели и возвращает номер полученной версии. Например, нужная внешняя операция предоставляется `mlflow.register_model`. Обучение повторно не запускается.

Не используй в качестве callback всю функцию первоначальной публикации из второго задания, если она назначает оба aliases. Восстановление здесь должно зарегистрировать результат и сохранить прежнего champion.

SDK может оборачивать сетевую ошибку собственным исключением. В адаптере переводи в `ConnectionError` только распознанную недоступность соединения. Ошибочный URI, неподдерживаемая модель и отказ по правам не должны превращаться в ложное ожидание восстановления сети.

## Проверка функции

Из корня курса в основной среде Python:

```bash
make task TASK=04-mlflow/03-outage
```

[Тесты](test_task.py) вызывают callback с успехом и ошибками, проверяют JSON, сохранность исходного состояния, создание вложенного пути и повтор без новой регистрации. До реализации ожидается `NotImplementedError`.

## Ручной опыт остановки сервера

Сначала при работающем MLflow подготовь собственный pending и запомни, куда указывает champion. Локальный файл состояния находится у клиента. Исходная модель и run находятся в volume сервера.

Останови только сервис:

```bash
docker compose -f labs/mlflow/compose.yaml stop mlflow
```

Вызови свою `recover_registration` с настоящим SDK-адаптером. Проверь, что локальный JSON сохранил `pending`, исходную ссылку и прежнюю версию champion. Верни тот же сервер:

```bash
docker compose -f labs/mlflow/compose.yaml start mlflow
curl --fail --max-time 10 http://127.0.0.1:5001/health
```

Повтори операцию, передав сохранённый JSON. Ожидаются зарегистрированная версия и связь с прежним run. Проверь champion через клиент: он не должен переместиться. Вызови функцию ещё раз с возвращённым `registered` состоянием. Новая версия не создаётся.

## Проверка настоящего SDK на сервере

```bash
MLOPS_RUN_INTEGRATION=1 MLOPS_RUN_WRITES=1 MLFLOW_TRACKING_URI=http://127.0.0.1:5001 python -m pytest modules/04-mlflow/tasks/03-outage/test_task.py -m integration -q
```

Тест создаёт собственные ресурсы и вызывает твою функцию. Для первой попытки искусственно задаётся отказ до запроса. Следующая попытка действительно регистрирует сохранённую SDK-модель. Проверяются исходный run, локальный JSON, отсутствие новой версии при повторе и неизменный champion.

Искусственный отказ позволяет воспроизвести переход состояний, но не выключает сервер. Ручной опыт выше отдельно проверяет обработку настоящей недоступности. Ситуация, когда версия создана, а ответ потерян, разобрана в [границах восстановления](../../README.md#регистрация-после-сетевого-отказа). Одной локальной записи JSON для её разрешения недостаточно.

## Завершение

Сохрани описание выпуска, состояние регистрации и доступ к исходному артефакту. Останови стенд через `docker compose -f labs/mlflow/compose.yaml down`, сохранив volume. Обучение и артефакты не нужно удалять для повторной попытки регистрации.
