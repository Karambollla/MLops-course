# Память, SSE и корпус запросов

[Теория](../../README.md) · [Практика модуля](../../practice.md) · [Подсказки](../../hints.md)

## С чего начать

В solution.py реализуй `weights_bytes(parameters, bytes_per_parameter=2)` и `kv_cache_bytes(layers, kv_heads, head_dim, context, concurrency, bytes_per_element=2)`. Все значения — положительные int без bool. Формула KV дана в теории; накладные buffers в неё не входят. `sse_contents(lines)` возвращает непустые content chunks из строк data: JSON, игнорирует role/heartbeat/пустые строки, останавливается на [DONE]; событие error и повреждённый JSON — ValueError. Здесь каждая data-строка содержит один полный OpenAI JSON event. В prompts.json уже есть 20 запросов разной длины для будущего benchmark; при желании замени их своим корпусом; запуск LLM для этой задачи не нужен.

Подготовь [основное окружение](../../../../SETUP.md). Все команды ниже выполняются из корня курса. Платформа задания: **cpu**. Функции и ожидаемые результаты описаны также в `test_task.py`; тесты используют небольшие фиксированные данные.

## Исходное задание

1. Вызови weights_bytes для 500000000 и 7000000000 параметров FP16; ожидаются 1000000000 и 14000000000 байт.
2. Вызови kv_cache_bytes с layers=24, kv_heads=8, head_dim=64, context=2048, bytes_per_element=2 и concurrency=1/8. Ожидаются 100663296 и 805306368 байт без дополнительных buffers.
3. Прогони SSE-fixtures из тестов: служебный chunk игнорируется, непустой content выдаётся, [DONE] останавливает поток, error вызывает ValueError. Используй готовый prompts.json как корпус для следующего задания; при желании замени его своими запросами.

Это вычисляемые результаты функций; отдельный файл с объяснением действий не нужен.

Для этих заданий не нужны платные API и фиктивный сервер.

## Проверка

```bash
make task TASK=16-llm-serving/01-memory-contract
```

У этой задачи проверяются функции: запускай их тестами, отдельного CLI нет.

До реализации функции ожидается `NotImplementedError`. Реализуй заготовку, сохраняя контракт функций из тестов. Офлайн-тест не подтверждает действия на внешнем стенде: проверки, требующие работающего сервиса, включаются явно через `MLOPS_RUN_INTEGRATION=1`.

## Результат

Функции должны проходить проверки положительных и отрицательных случаев. Для собственного эксперимента сохраняй исходные измерения в `work/`: они пригодятся для повторного сравнения. Отдельное письменное резюме не требуется. После работы останови стенд по инструкции practice.md.
