## Что можно проверить до GPU-запуска

Нужно заранее отличить объём весов от растущего cache и полезный текст от служебных событий потока. Для этого достаточно CPU-расчётов и фиксированных строк протокола: скачивание модели и платные API не нужны. Прочитай [память](../../README.md#веса-и-kv-cache-в-байтах), [SSE-контракт](../../README.md#streaming-и-sse-контракт) и [определения tokens](../../README.md#tokens-prefill-и-decode).

Уже предоставлены `solution.py`, тесты и `prompts.json` с 20 запросами разной длины для следующего benchmark. Здесь вход — числа и строки, выход — числа байтов и content chunks. Нужны только [основное окружение](../../../../SETUP.md) и локальный CPU.

## Контракт расчётов

Реализуй `weights_bytes(parameters,bytes_per_parameter=2) -> int` и `kv_cache_bytes(layers,kv_heads,head_dim,context,concurrency,bytes_per_element=2) -> int`. Все аргументы — положительные целые без bool; ноль, отрицательное, дробное число и bool вызывают ValueError. Возвращаются байты, не GB/GiB.

Для 500000000 FP16-параметров ожидается 1000000000 байт, для 7000000000 — 14000000000. В KV используй именно kv_heads, а не query heads. Для layers=24, kv_heads=8, head_dim=64, context=2048, bytes_per_element=2 и concurrency=1 ожидается 100663296 байт, при concurrency=8 — 805306368. Формула не включает buffers и другие расходы engine, поэтому результат нельзя принимать за полный VRAM budget.

## Контракт SSE

`sse_contents(lines) -> list[str]` принимает уже собранные строки: каждая `data:` содержит один полный JSON event совместимого chat streaming. Возвращаются непустые `choices[].delta.content` chunks по порядку. Пустые строки, heartbeat и role-only metadata игнорируются; `[DONE]` завершает обработку, JSON после него не читается. Event с `error` и повреждённый JSON до завершения вызывают ValueError.

Например, role-only event, затем content `"Hel"`, content `"lo"`, DONE и испорченная строка после DONE должны дать `["Hel","lo"]`. Это два content chunks, не обязательно два tokens. Parser упражнения не собирает сетевые фрагменты и не является универсальной реализацией всех многострочных SSE events.

## Проверка и использование результата

```bash
make task TASK=16-llm-serving/01-memory-contract
```

Тесты вызывают функции, CLI нет. `prompts.json` уже готов к использованию; можно заменить его собственным фиксированным корпусом. Перед реальным сравнением длины считают tokenizer-ом выбранной модели с chat template: длина строки в символах не равна количеству tokens.

Результаты функций помогают проверить арифметику и протокол; они не подтверждают загрузку модели или вместимость GPU. Стенд здесь не запускается, останавливать нечего. Дополнительный файл с пересказом действий не нужен.
