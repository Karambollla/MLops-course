# TensorRT-LLM: checkpoint, engine и Triton backend

[Модуль и подготовка](../../README.md#подготовка-к-заданиям) · [Все задания модуля](../../README.md#задания) · [Окружение курса](../../../../SETUP.md)

## Что изучается

TensorRT-LLM может требовать преобразования checkpoint и сборки engine под модель, dtype, shapes и GPU. Triton backend затем загружает engine. Ensemble может включать токенизацию и обработку результата. Открытый shell в контейнере не подтверждает ни сборку, ни inference.

Это справочное руководство. API-зависимые сценарии генерации TensorRT-LLM и соответствующего Triton backend пропущены. Обращения к LLM endpoints и их имитация не входят в практику. Проходить GPU-лабораторную ради этого раздела не нужно.

## Путь данных и артефактов

| Этап | Вход | Результат |
|---|---|---|
| Checkpoint | Model ID, immutable revision и tokenizer | Сохранённые веса и конфигурация архитектуры |
| Conversion | Совместимый checkpoint и поддерживаемый путь релиза | Представление весов для builder |
| Build | Веса, dtype, shapes/лимиты и GPU | Engine и метаданные сборки |
| Repository | Engine, backend config и tensor names | Структура загрузки Triton |
| Serving | Repository и совместимый runtime | Обработка запросов. В этом курсе не выполняется |

Изучи [архивное руководство backend 25.06](https://docs.nvidia.com/deeplearning/triton-inference-server/archives/triton-inference-server-2560/user-guide/docs/tensorrtllm_backend/README.html): requirements, conversion/build, model repository и связь preprocessing с engine. Сопоставляй примеры со встроенными версиями выбранного образа. Тег 24.07 внутри иллюстрации не делает engine совместимым с 25.06. Поддержку Qwen нельзя предполагать только из-за её использования в другом runtime.

Файл [tensorrt-llm.sh](../../../../labs/llm/tensorrt-llm.sh) служит справочным примером контейнерной среды с GPU. Он не собирает engine автоматически, а результаты без bind mount исчезают вместе с временным контейнером. Чтение этого файла не считается runtime-опытом.

## Разбор справочного shell-скрипта

Команды этого скрипта в практике не выполняются. В нём нет учебной Python-функции, checkpoint-конвертера или готового engine.

| Аргумент | Что означает | Следствие для артефактов |
|---|---|---|
| `docker run` | Создание отдельного контейнера из указанного image | Это ещё не запуск Triton server |
| `--rm` | Удаление контейнера после завершения | Без внешнего монтирования файлы внутри будут потеряны |
| `-it` | Интерактивный терминал | Скрипт открывает shell и ждёт действий человека |
| `--gpus all` | Передача доступных GPU в контейнер | Требуются совместимые NVIDIA driver/runtime на Linux |
| `--shm-size=2g` | Размер shared memory контейнера | Не увеличивает VRAM |
| `-p 127.0.0.1:8000:8000`, `8001`, `8002` | Публикация HTTP, gRPC и metrics-портов на loopback | Само назначение портов не запускает слушающие процессы |
| `25.06-trtllm-python-py3` | Тег образа Triton с TensorRT-LLM | Версии builder/backend должны соответствовать выбранному образу |
| `bash` | Команда внутри контейнера | Conversion, build и serving не выполняются автоматически |

`dtype` определяет формат чисел, shapes и лимиты задают допустимые размеры входов. Эти параметры относятся к сборке engine, но в данном скрипте builder не вызывается. Переменные окружения и bind mount для сохранения engine здесь не заданы. Для чтения скрипта и руководства не нужны GPU или установленный Docker.

## Границы сравнения

Разные модели, tokenizer, длины запросов или cache делают сравнение engines несопоставимым. Engine может зависеть от GPU и релиза TensorRT. Не указывай скорость или поддержку hardware по результату чтения конфигурации. Подробнее — [TensorRT-LLM и Triton](../../README.md#tensorrt-llm-и-triton).

В руководстве нет автоматических тестов. Локальные расчёты памяти и streaming-метрик выполняются в предыдущих темах. Они не подтверждают генерацию через API.
