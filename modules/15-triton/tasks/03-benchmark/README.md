# Сравнение inference latency

[Теория](../../README.md) · [Практика модуля](../../practice.md) · [Подсказки](../../hints.md)

## С чего начать

Реализуй `latency_summary(rows, elapsed_seconds, min_requests=200)`: p50_ms/p95_ms по latency_ms всех запросов (linear quantile), throughput_rps=len(rows)/wall_seconds, error_ratio для status>=400. Условия: достаточно измерений, конечные неотрицательные задержки, положительное elapsed_seconds, статусы HTTP. Для unit-фикстур min_requests можно уменьшить; полный benchmark выполняй с минимум 200 и одинаковыми concurrency/data/warmup. Сохрани отдельные исходные строки.

Подготовь [основное окружение](../../../../SETUP.md). Все команды ниже выполняются из корня курса. Платформа задания: **linux-x86_64**. Функции и ожидаемые результаты описаны также в `test_task.py`; тесты используют небольшие фиксированные данные.

## Исходное задание

Сравни один и тот же набор строк в FastAPI и Triton. Прогрей модель, затем выполни минимум 200 запросов при concurrency 1 и 4; запиши p50/p95, throughput, ошибки, batch и ресурсы. Без совместимого Triton-стенда можно выполнить CPU-тест вычисления метрик. Для примера три latency 10/20/30 ms за 1 s при одном ответе 500 дают p50=20 ms, p95=29 ms, throughput=3 rps и error_ratio=1/3. Это ручной пример определения метрик, не результат реального сравнения. План или текстовый отчёт не требуются.

## Проверка

```bash
make task TASK=15-triton/03-benchmark
```

У этой задачи проверяются функции: запускай их тестами, отдельного CLI нет.

До реализации функции ожидается `NotImplementedError`. Реализуй заготовку, сохраняя контракт функций из тестов. Офлайн-тест не подтверждает действия на внешнем стенде: проверки, требующие работающего сервиса, включаются явно через `MLOPS_RUN_INTEGRATION=1`.

## Результат

Функции должны проходить проверки положительных и отрицательных случаев. Для собственного эксперимента сохраняй исходные измерения в `work/`: они пригодятся для повторного сравнения. Отдельное письменное резюме не требуется. После работы останови стенд по инструкции practice.md.
