## Где работать и контракт

Основной starter: `modules/03-service-ci/tasks/03-ci/ci-runs.json` (пока пустой массив). В своём репозитории используй `.github/workflows/check.yml`: намеренно сломай контрактный тест в отдельной ветке, дождись failure; исправь и дождись success. Вставь реальные записи {sha: полный commit SHA, branch, conclusion, url, run_number: целое, passed_checks: список}. Для зелёного run passed_checks содержит tests и structure после чтения логов соответствующих шагов. Красный run должен предшествовать зелёному в той же ветке и относиться к другому commit. Публикация image и registry secrets не нужны.

`solution.py` — необязательный сборщик `collect_ci_runs(repository: str, branch: str) -> list[dict]` через read-only GitHub API; ручной экспорт допустим. Автотесты напрямую проверяют ci-runs.json; URL и значения сами по себе не доказывают реальный CI. Ручная приёмка: открыть оба run, проверить причину падения и успешные логи, сравнить команды с локальными.

## Среда и зависимости

Базовая среда из SETUP: Python, pytest; CPU, Linux/macOS.

Зависит от 03-service-ci/01-api-contract; GitHub требуется только для практического CI опыта. Базовые локальные тесты — offline. Ручная приёмка: команды локально совпадают с workflow, красный run падает на намеренно сломанном контракте, зелёный проверяет исправление.

## Запуск и результат

Из корня репозитория:

```bash
make task TASK=03-service-ci/03-ci
```

До заполнения ci-runs.json ожидается RED на пустой истории; необязательный сборщик отдельно содержит NotImplementedError. После реализации все offline-тесты должны быть зелёными. Они создают временные данные через pytest tmp_path; полный housing автоматически не скачивается.

CLI не требуется: после реального опыта заполни ci-runs.json и выполни make task.

## Требования практического опыта

Прочитай `.github/workflows/check.yml`. В собственном репозитории намеренно сломай контрактный тест в отдельной ветке и убедись, что CI красный. Исправь и проверь зелёный статус. Публикация образа и секреты registry в этом задании не нужны.

## Приёмка и очистка

Пройди все тесты `test_task.py`, сохрани перечисленные артефакты и добавь объяснение решений/ограничений в `report.md`. Для инфраструктурных опытов приложи реальные команды и вывод: offline проверки не доказывают развёртывание, доступность удалённого сервера или качество объяснения. Ручная оценка: воспроизводимость шагов, соответствие исходному контракту, объяснение причины сбоя и корректное восстановление.

После опыта останови стенд: `docker compose -f labs/housing/compose.yaml down`. Uvicorn останови Ctrl+C. Не удаляй volume без экспорта истории; артефакты `work/` сохрани для следующих модулей.
