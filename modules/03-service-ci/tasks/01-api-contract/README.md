## Зачем проверять числа через HTTP

Предоставленный API уже отвечает на запросы. Твоя задача — доказать, что он применяет ту же модель к тем же признакам и корректно отказывает на неверном входе. Одного 200 недостаточно: перепутанные столбцы всё ещё могут дать конечный прогноз. Схема преобразования описана в [разделе о файлах и сервисе](../../README.md#какие-файлы-превращаются-в-сервис), ожидаемые отказы — в [разборе запроса](../../README.md#разобранный-запрос-и-независимые-ошибки).

## Что уже готово

В `labs/housing/src/housing/api.py` есть `create_app` и маршруты; второй сервер писать не нужно. Для тестов используются маленький собственный Pipeline, доверенный bundle во временной папке и TestClient в контексте lifespan. Для сетевого опыта нужна экспортированная [модель кандидата](../../../01-ml/housing.ipynb). В `solution.py` реализуются проверка payload и набор вызовов API, а в этой папке добавляются интеграционные сценарии.

Если Pipeline на двух входных строках вернул `[1.0,2.0]`, HTTP должен вернуть два близких числа, нужный `model_version` и `target_unit="100000 USD"`. Перестановка JSON-ключей не меняет ответ. Изменение одного числа на 9.0 при коде 200 должно провалить проверку. Отдельно сравни отсутствие модели с несовместимым bundle: первое сохраняет `/live` 200 и даёт 503 готовности, второе прерывает startup. Для NaN/Infinity убедись, что запрос достиг сервера, а не был отвергнут сериализатором клиента.

## Где работать и контракт

Редактируй `modules/03-service-ci/tasks/01-api-contract/solution.py`. Дополнительные тесты размещай в этой же папке.

`check_prediction_response(payload: dict, expected, model_version: str) -> None` проверяет ровно ключи predictions/model_version/target_unit, размер batch, конечные прогнозы и allclose с rtol=1e-6, atol=1e-8; единица "100000 USD"; нарушение — ValueError. `exercise_api(client, pipeline, batch, model_version: str) -> None`: client — FastAPI TestClient уже в lifespan, batch — DataFrame FEATURES; сравни HTTP /predict и Pipeline, переставь JSON-ключи, проверь пустой/257 batch, missing/extra поля, строки/bool вместо чисел и NaN/Infinity → 422. При отсутствии модели проверь live=200, ready/predict=503 отдельным тестом. Физически добавь свои интеграционные тесты в эту папку, используя shared housing.api; код API уже предоставлен, не создавай второй сервер. Несовместимый bundle должен сорвать startup.

## Среда и зависимости

Базовая среда, fastapi/httpx/joblib/pandas/numpy/sklearn из housing; CPU.

Зависит от ML-notebook модуля 01 и манифеста. Сверь имя payload с labs/housing/request.json и API. Тесты создают только свой доверенный bundle, сеть не нужна.

## Запуск и результат

Из корня репозитория:

```bash
make task TASK=03-service-ci/01-api-contract
```

Тесты функций работают offline на маленьких входах и временных файлах. До реализации ожидается `NotImplementedError`; ошибка импорта означает проблему подготовки среды. Проверка функций не заменяет описанный опыт на данных или стенде.

Это задание использует функции; импортируй заготовку через `course_tasks.load_task("03-service-ci/01-api-contract")` из Python. CLI не требуется.

## Требования практического опыта

```bash
make test
uvicorn housing.api:app --host 127.0.0.1 --port 8000
```

Без модели проверь `/live` → 200, `/ready` → 503, валидный `/predict` → 503. С обученным bundle `/ready` и `/predict` возвращают 200. Запрос есть в `labs/housing/request.json`.

Добавь интеграционные тесты: совпадение predict HTTP и pipeline, перестановка JSON-ключей, NaN/Infinity, несовместимый bundle и неправильное количество строк. Неверная схема запроса должна давать 422 до выполнения модели.

## Приёмка и очистка

Запусти указанную выше команду `make task` после реализации и исправления ошибок. Проверяемые случаи перечислены в соседнем `test_task.py`.

После опыта останови стенд: `docker compose -f labs/housing/compose.yaml down`. Uvicorn останови Ctrl+C. Не удаляй volume без экспорта истории; артефакты `work/` сохрани для следующих модулей.

## Пример корректного результата

Без модели GET /live → 200, GET /ready и валидный POST /predict → 503. С совместимым bundle ready/predict → 200; пустой batch → 422. Порядок JSON-ключей не меняет прогноз; несовместимый bundle не проходит startup.
