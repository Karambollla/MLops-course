# Восстановить эксперимент

[Подготовка](../../README.md#подготовка-к-заданиям) · [Все задания](../../README.md#задания) · [Теория](../../README.md)

## Зачем повторять обучение отдельно

Успешная загрузка старого joblib доказывает, что сохранился объект, но не что процесс обучения можно восстановить. Теперь нужно заново получить модель по тем же входам в отдельном окружении и сравнить её поведение. Разница между восстановлением артефакта и повторением процесса, а также формула допуска разобраны в [теории повторения](../../README.md#два-вида-повторения-и-численный-допуск).

## Исходное состояние и два результата

Нужны сохранённая версия CSV из [DVC-темы](../01-data-version/README.md), [манифест и проверка bundle](../02-manifest/README.md), собственный `train` и закреплённые зависимости. Первая папка содержит исходный комплект четырёх файлов. Вторая получается новым обучением в отдельной папке, а не копированием первой. Для сравнения возьми первые 20 строк одного CSV, только столбцы FEATURES в каноническом порядке.

Функция `compare_runs` сначала проверяет сопоставимость происхождения, затем числа. При одинаковых входах и прогнозах `1.0`/`1.0+1e-9` ожидается `predictions_equal=True`. При прогнозах `1.0`/`2.0` — `False`. Если же во втором manifest другой SHA-256, нужен `ValueError`: вопрос о воспроизводимости одного запуска ещё не поставлен корректно. Метрики могут совпасть при разных прогнозах, поэтому два флага вычисляются независимо. Сохраняемые environment freeze и команды — технические входы восстановления, отдельное описание впечатлений не требуется.

## Подготовка

Нужны реализованные [проверки данных](../01-data-version/README.md), [манифест и проверка bundle](../02-manifest/README.md). Для тестов используются небольшие собственные файлы и модели во временных папках. Настоящий повтор обучения выполняется отдельно с твоим `train` и закреплёнными зависимостями.

## Что реализовать

Редактируй [solution.py](solution.py). Предоставлены импорты для чтения JSON, загрузки собственного joblib, численного сравнения и подключения предыдущего задания.

```python
def compare_runs(first: Path, second: Path, batch) -> dict:
    ...
```

| Аргумент | Тип и формат | Происхождение и назначение | Пример |
|---|---|---|---|
| `first` | `pathlib.Path` к папке первого запуска | Содержит исходные `manifest.json`, `split.json`, `metrics.json`, `model.joblib` | `Path("work/runs/original")` |
| `second` | `pathlib.Path` к папке повторного запуска | Такой же комплект после нового обучения с восстановленными входами | `Path("work/runs/restored")` |
| `batch` | `pandas.DataFrame` со столбцами ровно в порядке `FEATURES` | Одна и та же фиксированная таблица для двух моделей. Для практического опыта возьми первые 20 строк восстановленного CSV без target | `frame.loc[:, FEATURES].iloc[:20]` |

Сначала прочитай оба комплекта и проверь совместимость собственных bundle. Запуски должны иметь одинаковые `data_sha256`, `feature_order`, `seed`, `parameters` и разбиение. Содержимое `split.json` и манифестов должно описывать сопоставимые выборки. Иначе подними `ValueError`: это уже разные условия эксперимента.

Неверный порядок `batch.columns` тоже вызывает `ValueError`. Не переставляй его молча внутри сравнения. Порядок признаков является частью проверяемого контракта.

Затем независимо сравни прогнозы двух Pipeline на переданном `batch` и все MAE/RMSE из `metrics.json`. Для обоих сравнений используй `rtol=1e-6`, `atol=1e-8`. Сравнивать байты `model.joblib` вместо поведения модели нельзя. Совпавшие агрегированные метрики ещё не доказывают одинаковые прогнозы.

Результат — словарь с двумя булевыми значениями:

| Поле | Смысл |
|---|---|
| `predictions_equal` | Прогнозы на одном batch совпали в пределах допуска |
| `metrics_equal` | Все сохранённые MAE/RMSE совпали в пределах допуска |

При сопоставимых входах прогнозы `1.0` и `1.0 + 1e-9` считаются близкими. Прогнозы `1.0` и `2.0` дают `predictions_equal=False`. Другой хеш данных вызывает исключение, а не просто `False`. Версии среды сохраняй и сверяй по зависимостям отдельно: численная эквивалентность и тождественность окружений — разные проверки.

## Проверка функций

Из корня репозитория:

```bash
make task TASK=02-reproducibility/03-reproduce
```

Тесты функций работают offline на маленьких входах и временных файлах. До реализации ожидается `NotImplementedError`. Ошибка импорта означает проблему подготовки среды. Проверка функций не заменяет описанный опыт на данных или стенде.

Это задание использует функции. Импортируй заготовку через `course_tasks.load_task("02-reproducibility/03-reproduce")` из Python. CLI не требуется.

## Повторное обучение

Сохрани окружение и команды так, чтобы новая временная директория получала те же данные, split и метрики в пределах допуска. Добавь отрицательную проверку: изменённый SHA-256 или другой порядок признаков не должен незаметно обслуживаться как прежняя модель.

## Пример корректного результата

Два эквивалентных запуска дают `{"predictions_equal": true, "metrics_equal": true}`. Изменённые прогнозы дают predictions_equal=false. Другой SHA данных вызывает ValueError. Сравниваются числа с допуском, а не побайтовое равенство pickle.

## Завершение

Запусти указанную выше команду `make task` после реализации и исправления ошибок. Проверяемые случаи перечислены в соседнем `test_task.py`.

Docker не требуется. Сохрани CSV, указатели DVC, manifest, split и модель до проверки восстановления. Учебные demo/remote удаляй только после сохранения нужных версий в другом месте. Окружение можно завершить `deactivate`.
