# Восстановить данные

[Подготовка](../../README.md#подготовка-к-заданиям) · [Все задания](../../README.md#задания) · [Теория](../../README.md)

## Зачем восстанавливать байты, а не имя файла

Обученная модель зависит от содержимого CSV. Если файл изменился по прежнему пути, повтор той же команды уже проверяет другой эксперимент. Здесь контрольная сумма делает изменение наблюдаемым, а DVC связывает Git-версию небольшого указателя с данными в отдельном хранилище. Сначала прочти [цепочку Git/DVC](../../README.md#как-git-и-dvc-восстанавливают-одну-версию) и [смысл SHA-256](../../README.md#что-именно-доказывает-контрольная-сумма).

## Исходное состояние и разделение работы

Нужен CSV `work/housing.csv`, использованный [кандидатом](../../../01-ml/housing.ipynb). Работай с его копией в `work/dvc-demo`, исходный файл курса сохраняется. В `solution.py` реализуются две операции над файлами: потоковый хеш и отказ при несовпадении восстановления. DVC/Git-команды выполняются отдельно в учебном репозитории по [подготовке практики](../../README.md#подготовка-к-заданиям). Автотест не заменяет удаление копии и её получение из remote.

Например, `x,y\n1,2\n` и `x,y\n1,3\n` имеют одинаковый размер, но разные SHA-256. После восстановления V1 ожидается хеш V1. После выбора commit V2 и `dvc checkout` — хеш V2. Если поменялся только commit, а рабочие байты остались V1, второй опыт не завершён. Сохрани соответствующие указатели и данные в remote до окончания проверки обеих версий. Служебный checksum DVC не нужно вручную заменять своим SHA-256.

## Подготовка

Для тестов хеша достаточно основной Python-среды. Для восстановления данных подготовь отдельное окружение с DVC и учебный репозиторий по [инструкции модуля](../../README.md#подготовка-к-заданиям). Работай с копией `work/housing.csv` внутри `work/dvc-demo`. Изменение этой копии не должно менять исходный датасет курса.

## Что реализовать

Редактируй [solution.py](solution.py). Импорты `hashlib` и `Path` уже предоставлены.

### `sha256_file`: контрольная сумма содержимого

```python
def sha256_file(path: Path, chunk_size: int = 65536) -> str:
    ...
```

| Аргумент | Тип и формат | Происхождение и назначение | Пример |
|---|---|---|---|
| `path` | `pathlib.Path` к существующему файлу | CSV или другой файл, байты которого нужно идентифицировать | `Path("work/housing.csv")` |
| `chunk_size` | Положительное целое число. По умолчанию `65536` | Максимальный размер одного читаемого блока в байтах. Ограничивает память при чтении большого файла | `4096` |

Возвращай SHA-256 как строку из 64 шестнадцатеричных символов. Открывай файл в бинарном режиме и обновляй хеш последовательными блоками. Чтение целого файла через `read_bytes` не соответствует потоковому контракту. Разный `chunk_size` не должен менять результат для одинаковых байтов.

Неположительный `chunk_size` вызывает `ValueError`. Ошибки доступа к пути не скрывай: отсутствие файла должно оставаться ошибкой файловой операции. Пустой существующий файл имеет определённую SHA-256 и тоже корректно обрабатывается.

```python
def verify_restore(original_hash: str, restored: Path) -> None:
    ...
```

| Аргумент | Тип и формат | Происхождение и назначение | Пример |
|---|---|---|---|
| `original_hash` | Строка SHA-256, записанная до удаления или переключения данных | Эталон, с которым сравнивается восстановленный файл | Результат `sha256_file` для версии V1 |
| `restored` | `pathlib.Path` к восстановленному файлу | Рабочая копия после `dvc pull` или `dvc checkout` | `Path("work/dvc-demo/housing.csv")` из корня курса |

Если хеш совпадает, функция возвращает `None`. При несовпадении выбрасывается `ValueError`. Она не исправляет файл и не запускает DVC. Если файла нет, это тоже ошибка, а не успешное восстановление.

Например, `x,y\n1,2\n` и `x,y\n1,3\n` занимают одинаковое число байтов, но имеют разные хеши. Размер файла и его имя не заменяют проверку содержимого.

## Проверка функций

Из корня репозитория:

```bash
make task TASK=02-reproducibility/01-data-version
```

Тесты функций работают offline на маленьких входах и временных файлах. До реализации ожидается `NotImplementedError`. Ошибка импорта означает проблему подготовки среды. Проверка функций не заменяет описанный опыт на данных или стенде.

Это задание использует функции. Импортируй заготовку через `course_tasks.load_task("02-reproducibility/01-data-version")` из Python. CLI не требуется.

## Работа с версиями данных

Запиши SHA-256 CSV. Удали только рабочий CSV, сохранив `.dvc`-указатель, и восстанови `dvc pull`. Сравни хеши. Затем добавь собственную вторую версию CSV и покажи переключение данных через предыдущий Git commit и `dvc checkout`. Исходный датасет курса при этом не меняется.

## Проверка настоящего DVC

Создай отдельную среду по SETUP и установи `python -m pip install -r labs/dvc/requirements.txt`, затем подключи локальный пакет: `python -m pip install --no-deps -e labs/housing`.

```bash
MLOPS_RUN_SDK=1 python scripts/run_task.py test 02-reproducibility/01-data-version -- -m sdk
```

Проверка использует настоящий DVC CLI и локальный remote во временной папке: add/push, удаление файла и локального cache, pull. Восстановленные bytes сверяются с исходными и с твоими `sha256_file`/`verify_restore`. Она не обращается к `work/` и не заменяет самостоятельный опыт с двумя Git/DVC-версиями. Отсутствие DVC при включённом флаге — ошибка подготовки, незавершённая функция — `NotImplementedError`.

## Пример корректного результата

После dvc pull SHA-256 восстановленного CSV совпадает с исходным. После изменения хотя бы одного байта verify_restore поднимает ValueError. Автотесты проверяют хеш и содержимое, но не выполняют DVC-команды вместо тебя.
