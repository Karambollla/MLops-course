# Манифест и контракт

[Подготовка](../../README.md#подготовка-к-заданиям) · [Все задания](../../README.md#задания) · [Теория](../../README.md)

## Зачем модель должна объяснять свой вход

Файл с Pipeline загружается, но пока не отвечает, из каких данных он получен и какой порядок восьми признаков ожидает. Манифест связывает модель с данными, split, настройками и средой, а проверка bundle останавливает несовместимое использование до `predict`. Назначение полей и независимой копии описано в [разделе о снимке запуска](../../README.md#манифест-как-снимок-условий-запуска).

## Что готово и что реализовать

Используй четыре артефакта [обучения](../../../01-ml/housing.ipynb) и `sha256_file` из [предыдущей темы](../01-data-version/README.md). Сигнатура `build_manifest` уже задаёт входы. Она собирает обязательную структуру. Сведения о коде и источнике дополняют происхождение в программе обучения, но не меняют сигнатуру. `validate_bundle` проверяет доверенный уже загруженный объект и manifest. Она не обезвреживает небезопасный pickle.

Пример: после построения манифеста `split["train"]` содержит `[0,1]`. Если вызывающий код затем добавил в исходный список 99, в манифесте должны остаться `[0,1]`. Это проверяет, что результат является снимком. Во втором опыте переставь первые два имени `features`: совпадения множества имён недостаточно, должен возникнуть `ValueError`. Проверка хеша аналогично сверяет ожидаемый вход с `manifest.data_sha256`, а не только наличие непустой строки.

## Подготовка

Для проверок функций достаточно основной среды курса и реализованной `sha256_file` из [предыдущего задания](../01-data-version/README.md). Маленькие тесты создают собственный CSV и объект с методом `predict` во временной папке. Для соединения с обучением понадобится реализация `train` из ML-notebook.

## Что реализовать

Редактируй [solution.py](solution.py). В нём уже подготовлены `deepcopy`, `Path`, `load_task` и `FEATURES`.

### `build_manifest`: сохранить условия запуска

```python
def build_manifest(
    data_path: Path, seed: int, split: dict, versions: dict, parameters: dict
) -> dict:
    ...
```

| Аргумент | Тип и формат | Происхождение и назначение | Пример |
|---|---|---|---|
| `data_path` | `pathlib.Path` к исходному CSV | Тот файл, который использует обучение. По его байтам вычисляется SHA-256 | `Path("work/housing.csv")` |
| `seed` | `int` | Значение, переданное в разбиение и обучение. Нужен для повторения запуска | `42` |
| `split` | `dict` со списками позиций строк `train`, `validation`, `test` | Результат разбиения из ML-модуля. Фиксирует состав выборок | `{"train": [0, 1], "validation": [2], "test": [3]}` |
| `versions` | `dict`, допускающий вложенные структуры | Версии среды, собранные вызывающей программой. Для пакетов можно использовать `importlib.metadata.version` | `{"python": "3.12", "packages": {"numpy": "2.2.6"}}` |
| `parameters` | `dict`, допускающий вложенные структуры | Настройки реально обучаемой модели. Их передаёт вызывающий код | `{"estimator": {"alpha": 1.0}}` |

Возвращаемый словарь содержит `schema_version=1`, `seed`, `data_sha256`, `split`, `versions`, `parameters` и `feature_order=FEATURES`. `data_sha256` вычисли через функцию предыдущего задания. Восемь признаков должны сохранять канонический порядок.

Списки и вложенные словари в результате не должны зависеть от последующего изменения входных объектов. Например, добавление 99 в переданный `split["train"]` после вызова не меняет уже собранный манифест. Такая же независимость требуется для вложенных `parameters` и `versions`.

### `validate_bundle`: проверить совместимость

```python
def validate_bundle(bundle: dict, manifest: dict, expected_sha256: str) -> None:
    ...
```

| Аргумент | Тип и формат | Происхождение и назначение | Пример |
|---|---|---|---|
| `bundle` | Уже загруженный доверенный словарь модели | Содержит `schema_version`, `pipeline`, `features`, `model_version`. Проверяется до `predict` | Результат загрузки собственного `model.joblib` |
| `manifest` | Словарь с условиями обучения | Сверяет схему, порядок признаков и происхождение данных | Результат `build_manifest` или чтения собственного `manifest.json` |
| `expected_sha256` | Строка ожидаемой SHA-256 данных | Хеш нужной версии CSV, независимо выбранной вызывающим кодом | Контрольная сумма восстановленных данных |

Проверь версию схемы 1 у bundle и манифеста. `pipeline` должен иметь вызываемый метод `predict`. `features` в bundle и `feature_order` в манифесте должны точно совпадать с `FEATURES`, включая порядок. Версия модели `model_version` должна быть непустой. `manifest["data_sha256"]` должен совпадать с `expected_sha256`.

При корректном комплекте верни `None`. При несовместимости подними `ValueError` до прогнозирования. Например, перестановка двух признаков или другой хеш должны остановить работу, даже если файл модели успешно прочитан.

Проверка не делает чужой pickle безопасным. Десериализуй только собственные доверенные артефакты.

## Проверка функций

Из корня репозитория:

```bash
make task TASK=02-reproducibility/02-manifest
```

Тесты функций работают offline на маленьких входах и временных файлах. До реализации ожидается `NotImplementedError`. Ошибка импорта означает проблему подготовки среды. Проверка функций не заменяет описанный опыт на данных или стенде.

Это задание использует функции. Импортируй заготовку через `course_tasks.load_task("02-reproducibility/02-manifest")` из Python. CLI не требуется.

## Подключение к обучению

Подключи эти функции к `train` в ML-notebook. Сведения о происхождении дополни в вызывающем коде: Git commit либо явное отсутствие Git с checksum исходников, источник CSV, дата получения, единицы измерения и ограничения. Не включай секреты и обязательные абсолютные пути своей машины. При повторном обучении через CLI `manifest.json` содержит seed, хеш CSV, split, версии, параметры и список признаков. Bundle `model.joblib` — словарь с ключами `schema_version=1`, `pipeline`, `features`, `model_version`. Точные требования есть в [контракте](../../../../labs/housing/README.md). Сделай два запуска с одинаковыми входами и сравни прогнозы на фиксированных 20 строках через `numpy.allclose` с `rtol=1e-6`, `atol=1e-8`.

## Пример корректного результата

Для собственного bundle с правильной схемой и SHA проверка завершается без исключения. Перестановка features, другой data_sha256 или пустой model_version приводят к ValueError до predict. Манифест не меняется при последующем изменении переданного исходного dict.
