# Резюме и выбор следующего шага

[Теория](../../README.md) · [Практика модуля](../../practice.md) · [Подсказки](../../hints.md)

Рекомендации и примеры формулировок. Обязательного резюме, списка вакансий, отчёта и тестов здесь нет. Публикация материалов — отдельное решение автора.

## Примеры честных пунктов

- «Разработал учебный локальный pipeline обучения и API для [задача]; MAE на фиксированном test изменилась с [baseline] до [candidate]; данные и модель связаны через [реальный hash/manifest]».
- «Добавил проверку контракта входа и readiness модели; проверил [реальные ошибочные запросы] и восстановление версии [реальный ID]».
- «Сравнил [реально запущенные engines] на [hardware], [batch], concurrency [N] и одном корпусе: p95 [до] → [после] ms на [число] запросах после warmup; доля ошибок [значение]».

Это образцы с явными placeholders. Удаляй неподтверждённую часть, если измерений нет. Относительное снижение MAE вычисляется как `(baseline - candidate) / baseline * 100%` при положительном baseline. Например, 100 → 90 означает 10%; это арифметический пример, не результат курса.

Если GPU не было: «Изучил устройство KV cache и реализовал CPU-расчёт памяти и разбор SSE; практического запуска NVIDIA serving пока нет». Если ClearML использовался offline: «Применял ClearML в offline-режиме для [реальное действие]». Локальный учебный стенд не даёт оснований писать production, SLA или миллионы запросов.

## Как выбрать содержание

Для инфраструктурной роли выдели поставку, диагностику и восстановление; для ML-роли — данные, baseline, split и качество. В обоих случаях укажи собственный вклад. Ссылка на репозиторий полезна, если README позволяет понять задачу и воспроизвести доступную часть без секретов или закрытых данных.

Смотри реальные объявления интересующего рынка и отмечай повторяющиеся требования. Сопоставляй их с конкретным кодом или опытом. Например: «Python Pipeline — есть обучающий код и тест входа; Kubernetes — изучал manifests, кластер не администрировал; GPU serving — только теория». Следующий шаг выбирай по существенному пробелу для интересующей роли, а не по длине списка технологий.
