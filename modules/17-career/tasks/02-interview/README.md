# Вопросы на собеседовании с примерами ответов

[Теория](../../README.md) · [Практика модуля](../../practice.md) · [Подсказки](../../hints.md)

Материал для самостоятельного разговора. Ответы ниже — примеры рассуждения; они не утверждают, что эти действия уже выполнены в твоём проекте. Заполнять форму, записывать интервью или проходить тест не требуется.

## Данные и качество

**Как обнаружить training-serving skew?** Сравнить порядок и типы признаков, preprocessing и обработку пропусков на одном фиксированном входе. Затем проверить статистики реального трафика и обучающего snapshot. Один общий Pipeline уменьшает риск расхождения преобразований, но не обнаруживает смену распределения данных сам по себе.

**Почему random split может переоценить качество?** Строки одного объекта или будущие наблюдения попадают в обе части. Для прогноза будущего использую разделение по времени, для новых объектов — по группам; все обучаемые преобразования fit только на train. Выбор зависит от того, как модель будет применяться.

**Какие данные нужны для актуальной MAE?** Предсказание, фактический target, ID и время события, версия модели, а также правила соединения и окно расчёта. Без пришедших target можно наблюдать технические метрики и drift признаков, но это не измерение текущей ошибки модели.

## Выпуск и восстановление

**Как откатить модель, если image не менялся?** Переключить ссылку на предыдущий immutable артефакт, дождаться загрузки, проверить версию и прогноз. Одного восстановления образа недостаточно, если модель загружается отдельно. В согласованном выпуске фиксирую пару image digest и model artifact.

**Что делать, если task упал после успешной публикации?** Сначала проверить внешний результат по устойчивому ID. Повтор должен распознать уже опубликованный выпуск или безопасно повторить операцию. Слепой повтор может создать дубль; откатывать без проверки тоже опасно.

**Почему up=1 не доказывает готовность?** Это доступность scrape endpoint для Prometheus. Процесс может отдавать метрики, пока модель не загрузилась. Отдельная readiness и реальный inference проверяют другие свойства; корректность прогнозов требует своей проверки.

## Инфраструктура и безопасность

**Чем Terraform state отличается от Ansible inventory?** State связывает описанные ресурсы с объектами провайдера и хранит сведения для планирования изменений. Inventory перечисляет управляемые хосты и группы для выполнения конфигурации. State может содержать чувствительные значения и требует контроля доступа.

**Как не отправить секреты в MLflow artifacts?** Явно выбрать безопасные параметры и файлы, не логировать environment целиком, исключить credential-файлы и проверить bundle перед загрузкой. Маскирование в терминале не удаляет секрет из файла. Случайно опубликованный credential нужно отозвать.

**Как воспроизвести запуск на другом worker?** Закрепить данные, код, зависимости, конфигурацию, модель и seed, хранить hashes и версии. При GPU также нужны сведения о runtime/hardware. Даже одинаковый seed не гарантирует побитовую идентичность разных устройств; задаю допустимое численное отклонение.

## Поиск и serving

**Когда lexical поиск полезнее vector?** Для точных error codes, имён и редких идентификаторов. Семантическая близость полезна для перефразированных запросов. Сравниваю на фиксированных qrels и могу соединить ранги через RRF; складывать raw scores разных движков без калибровки нельзя.

**Что ограничивает concurrency LLM-serving?** Память весов, KV cache, длина context/output, scheduler и вычислительная пропускная способность. Увеличение concurrency может повысить throughput и ухудшить TTFT. Нужны одинаковый корпус, версии и реальные измерения, а не вывод по одному короткому запросу.

**Какие компоненты убрать маленькой команде?** Сначала выяснить число пользователей, расписания, SLA, доступные навыки и стоимость сопровождения. Если есть один последовательный pipeline, локальное хранилище и простой scheduler могут быть достаточны. Распределённый orchestrator добавляю при конкретной потребности в зависимостях, повторах и общей эксплуатации.

Если вопрос выходит за опыт, допустимо сказать: «Сам это не запускал; понимаю [конкретный механизм], проверил бы [документацию и небольшой эксперимент]». Это даёт собеседнику точную границу знания.
