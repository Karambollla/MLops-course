# Границы Dockerfile, Terraform и Ansible

Это guide без сдачи таблицы или автоматических тестов строк.

| Инструмент | Вход и состояние | Повтор и восстановление |
|---|---|---|
| Dockerfile | Рецепт образа; образ/tag/digest в registry | Пересобрать образ; откат deployment на предыдущий digest |
| Terraform | HCL + привязки address→ID в state | plan сравнивает инфраструктуру; восстановление через reviewed plan/import |
| Ansible | Inventory/playbook + фактические файлы узла | Повтор приводит файлы к нужному виду; откат через прежний template/vars |

Пример изменения: новая Python-зависимость housing API требует образа Docker; новый контейнер/сеть — Terraform; изменение WORKERS на существующем узле — Ansible template+handler. Terraform state не хранится в Git; lock-файл provider хранится. Ansible Vault шифрует файлы, а HashiCorp Vault выдаёт доступ через отдельный сервис: это разные инструменты.

Для локального приложения на одном Compose-хосте достаточно Dockerfile+Compose; добавлять все три инструмента необязательно. Дополнительная практика: выделить SSH managed container и выполнить playbook по inventory вместо локального connection. Это отдельный узел, в отличие от запуска controller-контейнера.

Команды запускай из корня курса после [SETUP](../../../../SETUP.md). Python-тесты проверяют функции на фиксированных входах; они не подтверждают запуск стенда. Live-проверки включаются только `MLOPS_RUN_INTEGRATION=1`, читают существующий стенд и не создают/не удаляют ресурсы. При включённом флаге недоступные зависимости — ошибка с подсказкой.
