[Теория](../../README.md) · [Практика модуля](../../practice.md) · [Подсказки](../../hints.md)

## С чего начать

Заполни `comparison.json` и `comparison.md`: вход, состояние, повтор и откат для каждого инструмента, плюс собственное архитектурное решение. Автоматически проверяются только полнота и отсутствие противоречий. Аргументы сравни с ручной рубрикой.

Подготовь [основное окружение](../../../../SETUP.md). Все команды ниже выполняются из корня курса. Платформа задания: **cpu**. Функции и ожидаемые результаты описаны также в `test_task.py`; тесты используют небольшие фиксированные данные.

## Исходное задание

Составь таблицу Dockerfile/Terraform/Ansible: что описывает каждый, где хранится состояние, как повторить и откатить изменение. Дополнительное задание — отдельный SSH-enabled managed container; он не нужен для интенсива.

## Проверка

```bash
make task TASK=12-ansible/03-tool-boundaries
```

Для Python CLI:

```bash
python scripts/run_task.py run 12-ansible/03-tool-boundaries -- --help
```

До реализации функции ожидается `NotImplementedError`; для отчётов — ошибка незаполненного поля. Исправляй заготовку или собственный результат, сохраняя ожидаемое поведение тестов. Офлайн-тест не подтверждает действия на внешнем стенде: проверки, требующие работающего сервиса, включаются явно через `MLOPS_RUN_INTEGRATION=1`.

## Критерии и завершение

Ручная рубрика: верно ли названы управляемые объекты; где реальные границы идемпотентности; как восстановить состояние; нужен ли инструмент именно твоему проекту. Непустая таблица сама по себе не доказывает правильность аргументов.
