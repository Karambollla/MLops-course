# Выбрать владельца изменения

[Модуль](../../README.md) · [Подготовка](../../README.md#подготовка-к-заданиям) · [Все задания](../../README.md#задания)

## Что разбираем

Одну настройку можно записать в образ, параметры создания контейнера и Ansible template. Если разные инструменты считают себя её владельцем, следующий запуск может вернуть другое значение. Для каждого изменения полезно определить: какой объект должен измениться и каким действием это проверяется.

Это разбор готовых артефактов курса. Новый стенд, Python-функция или отдельный документ не нужны. Используются [Dockerfile API](../../../../labs/housing/Dockerfile), [конфигурация Terraform](../../../11-terraform/tasks/01-repeat/main.tf) и [шаблон предыдущего задания](../02-template-handler/housing.env.j2).

## Проследить три изменения

| Потребность | Что и где изменяется | Как проверить применение и повтор |
|---|---|---|
| Housing API требует новую Python-библиотеку | Зависимости и рецепт Docker image | Собрать новый образ, запустить сервис и проверить нужную операцию |
| Нужен новый контейнер или другой опубликованный порт | Resource Terraform в `main.tf` | Просмотреть plan, применить, проверить объект и следующий no-op |
| Существующий узел должен получить новый env | Vars/template Ansible | Выполнить playbook, увидеть изменение и handler, затем повтор `changed=0` |

Dockerfile описывает содержимое образа. Terraform связывает объявления с объектами API через state. Ansible сопоставляет желаемые файлы с фактическими файлами узла. Эти границы подробнее разобраны [в главе](../../README.md#граница-dockerfile-terraform-и-ansible).

В неизменяемом контейнерном приложении WORKERS можно передать при создании контейнера, а не доставлять Ansible после запуска. В варианте с VM Ansible мог бы настроить файл сервиса на существующем узле. Выбор зависит от способа поставки: учебный env-файл второго задания сам не подключён к Housing API.

## Проследить возврат к прежнему состоянию

Для библиотеки нужен прежний проверенный image и повторный выпуск. Для ресурса Terraform меняется желаемая конфигурация, затем рассматривается новый plan. Удаление state не является откатом. Для env через Ansible применяются прежние vars/template и проверяется повтор. Ни один из этих шагов сам не откатывает внешние данные, созданные приложением.

Terraform мог бы передать адрес узла через output, а Ansible использовать его в inventory. В локальных заданиях это не связано: Nginx Terraform и controller Ansible — разные контейнеры. Сходство пути или имени файла не означает передачу результата между ними.

Разбор завершён, когда для каждого изменения можно указать один источник желаемого значения, исполняющий инструмент и наблюдаемый результат. Для локального Housing на одном Compose-хосте может быть достаточно Dockerfile и Compose. Новую инфраструктуру только ради участия всех инструментов создавать не требуется. Если task-local controller ещё существует, используй [очистку модуля](../../README.md#остановка-и-очистка).
