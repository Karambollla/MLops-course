## От записи к результату

Начнём с события `{"duration": 2.0}`. В Python такое отображение ключей в значения называется **словарём**, `dict`. Он похож на Go map: пустой `{}` тоже является корректным объектом, хотя в нём нет нужного поля. В первом упражнении пригодность каждого измерения проверяет твоя функция.

Для записей `[{"duration": 2}, {"duration": 4}, {"duration": True}]` подходят только первые два значения. Их сумма 6, количество 2, среднее 3.0. Булево `True` здесь не измерение. Это важно проверить явно: Python считает `bool` подтипом `int`.

Что вернуть, если подходящих значений вообще нет? `mean=None` обозначает отсутствие результата. Ноль означал бы посчитанное среднее и исказил бы смысл. После преобразования в JSON Python `None` станет `null`, а `True` станет `true`.

В условии требуется **конечное** положительное число: исключаются NaN и обе бесконечности. NaN может появиться после неопределённого вычисления и не равен самому себе. Условие `value > 0` не заменяет проверку конечности, потому что положительная Infinity его проходит. В задании для этого подготовлен `math.isfinite`.

## Имена, объекты и типы

В Go компилятор закрепляет тип переменной. В Python имя связывается с объектом при выполнении. Аннотация `records: list[dict]` сообщает ожидаемый вход читателю и редактору, но не запускает автоматическую проверку каждого поля. Правило о `duration` нужно реализовать в функции.

Передача и присваивание изменяемого объекта тоже требуют внимания. После `second = first` оба имени обращаются к одному списку. Поверхностная копия создаёт новый внешний контейнер, но оставляет общими вложенные объекты. Например, две конфигурации обучения могут случайно разделять один вложенный словарь:

```python
first = {"model": {"alpha": 1.0}}
second = first.copy()
second["model"]["alpha"] = 10.0
print(first["model"]["alpha"])  # 10.0
```

Читатель ожидал два независимых запуска, а изменение второго затронуло первый. Поэтому функция сводки не меняет переданные записи, а в дальнейшем манифест должен создавать независимый снимок условий.

Отсутствие значения проверяй согласно смыслу: `value is None` отличает его от нуля. Условие `if not value` объединяет `None`, ноль, пустой список и другие ложные значения. Не все они являются одной ошибкой.

## Коллекции и вычисления

Список `list` хранит последовательность записей, словарь `dict` — поля одной записи. Когда функция возвращает пару результатов, их можно объединить в кортеж `tuple`. В заданиях pandas так возвращаются две выровненные Series. Множество `set` пригодится, когда важно проверить уникальность или пересечение меток.

Для короткого преобразования удобно списковое выражение, list comprehension. Например, на уже корректных числах можно выбрать положительные значения:

```python
values = [-1.0, 2.0, 4.0]
positive = [value for value in values if value > 0]
print(positive)  # [2.0, 4.0]
```

Это только пример синтаксиса. У первой задачи строже входной контракт: там ещё нужны тип, исключение `bool` и конечность. Когда условий становится много, отдельная понятная функция легче проверяется, чем длинное выражение.

Для числовых расчётов дальше появятся массивы **NumPy**. Они хранят однородные значения и выполняют многие операции в скомпилированном коде. У массива есть **shape**, размеры по осям, и **dtype**, тип хранения. Таблица на pandas использует эти возможности, добавляя имена столбцов и метки строк. Передавать массив в модель без проверки формы так же рискованно, как декодировать сетевое сообщение по неправильной схеме.

## Функции, исключения и ресурсы

Одна функция сводки отвечает за допустимость измерений. При чтении файла появляются другие ошибки: файл не открылся или строка не является JSON. Эти границы полезно разделять, чтобы вызывающая программа могла отличить испорченную запись от ошибки среды.

Python передаёт ошибку через исключение. В контрактах курса `ValueError` означает неподходящее значение. Перехватывать его нужно там, где можно принять осмысленное решение: например, CLI выводит номер повреждённой строки и завершается с ошибкой. `except Exception: pass` скрывает и проблему входа, и собственный баг программы.

Файлы нужно закрывать независимо от успешности чтения. Блок `with` управляет временем жизни ресурса. Он напоминает `defer`, но ограничен конкретным блоком:

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "config.json"
    path.write_text('{"seed": 42}', encoding="utf-8")
    with path.open(encoding="utf-8") as stream:
        config = json.load(stream)
    print(config["seed"])  # 42
```

Внутренний блок закрывает файл. Внешний удаляет собственную временную папку. В настоящей программе путь входа передаёт пользователь, и удалять его после чтения не нужно.

Изменяемый аргумент по умолчанию, например `items=[]`, создаётся один раз при определении функции. Если требуется новый список на каждый вызов, передавай `None` и создавай список при выполнении. Иначе результат одного вызова может изменить следующий.

## Построчное чтение и контракт CLI

Теперь записи приходят из файла, который может быть намного больше доступной памяти. **JSONL**, JSON Lines, хранит отдельное JSON-значение в каждой строке. По условию второй задачи каждое значение должно быть объектом: `[]` является правильным JSON, но неподходящей записью. Номер ошибочной строки считается от 1.

Для последовательной обработки Python использует **итератор**, который отдаёт следующий элемент по запросу. **Генератор** описывает такой источник через `yield`. Этот пример показывает момент чтения:

```python
def measurements():
    print("получаем первое измерение")
    yield 2.0
    print("получаем второе измерение")
    yield 4.0

source = measurements()
print("источник создан")
print(next(source))
```

Сначала выводится «источник создан». До `next` тело генератора не выполняется. Аналогично ошибка второй строки JSONL должна возникнуть при запросе второй записи. После неё третья строка не читается. Агрегатору достаточно текущей суммы и количества, поэтому накопление `list(iterator)` перед расчётом не нужно.

Результат программы должен быть пригоден для другого процесса. **CLI** — интерфейс командной строки. **stdout** содержит один JSON со сводкой, **stderr** — сообщение об ошибке, а код завершения сообщает об успехе или отказе shell и будущему пайплайну. При повреждённой строке не печатай частичную успешную сводку: потребитель может принять её за завершённый результат.

В README второй темы показан точный путь `main → summarize_file → iter_records → summarize` и формат вывода. Строка с неверным `duration` проходит JSON-декодирование, но фильтруется агрегатором. Повреждённый JSON прерывает обработку файла.

## Таблица, индекс и форма массива

Для обучения нужны связанные колонки: признаки одного района и ответ для него. В pandas такая таблица называется **DataFrame**, а отдельный столбец или ряд с метками — **Series**. Числовой столбец может содержать пропуски или неожиданно стать строковым, поэтому перед `fit` третье задание строит сводку.

В ней `shape=[4, 2]` означает четыре строки и два столбца. `dtypes` показывает типы хранения, `missing` — число отсутствующих значений. Например, числовой `float64` и столбец `object` со строками требуют разной обработки.

Для понимания масштаба чисел считаются **квантили** — границы долей упорядоченного набора. Квантиль 0.5 называется медианой. У `[1, 2, 3, NaN]` пропуск учитывается отдельно, а квантили 0.25/0.5/0.75 по оставшимся значениям равны 1.5/2.0/2.5 при линейной интерполяции pandas. Текстовые столбцы в такой расчёт не входят.

Другая опасность — сопоставление разных объектов по позиции. Пусть есть цены и комиссии с одинаковыми именами, но разным порядком:

```python
import pandas as pd

prices = pd.Series([20, 10], index=["b", "a"])
fees = pd.Series([1, 2], index=["a", "b"])
print((prices + fees).to_dict())  # {'a': 11, 'b': 22}
print(prices.to_numpy() + fees.to_numpy())  # [21 12]
```

pandas соединяет по меткам: для `b` это `20 + 2`. После `to_numpy` метки потеряны и складываются первые элементы разных объектов. Оба действия успешно возвращают числа. Третье задание требует оставить общие метки в порядке левой Series, поэтому проверяй именно индекс и значения.

`.loc` выбирает строки по меткам, `.iloc` — по позиции. В Housing известная стоимость `MedHouseVal` является **target**, целевым ответом. Остальные столбцы являются признаками, из которых модель должна его предсказать. Target входит в сводку CSV, но не передаётся модели вместе с признаками. То же различие понадобится для текста письма и его класса или изображения и его метки.

## Как различать ошибки

| Наблюдение | Что проверить первым | Почему это важно |
|---|---|---|
| Среднее равно бесконечности | Конечность каждого принятого числа | Положительность не исключает Infinity |
| Один вызов изменил следующий | Общий список или изменяемый аргумент по умолчанию | Имена могут ссылаться на один объект |
| Ошибка JSON появляется слишком поздно | Нет ли `list(stream)` или чтения всего файла заранее | Ленивость проверяется порядком потребления |
| После сложения появились NaN | Совпадение индексов двух Series | pandas выравнивает метки, которых у другой стороны может не быть |
| CSV содержит `Unnamed: 0` | Не сохранён ли индекс через `to_csv` | Технический индекс не является признаком |

Зелёные маленькие тесты подтверждают правила функции на проверенных входах. Они не доказывают качество housing-данных и не заменяют просмотр вычисленной сводки. Для этой темы Docker и сетевые сервисы не нужны. Загрузчик housing впервые требует сеть только при получении датасета.

## Конкурентность

В дальнейшем обучение будет выполнять вычисления, а SDK — отправлять результаты по сети. Это разные виды работы. Сетевая операция может ждать ответа, тогда как обучение использует процессор. Добавление `async def` к синхронному `fit` не превращает его в неблокирующую операцию.

`asyncio` организует задачи, которые передают управление во время ожидания. По устройству это не полная замена Go-горутинам. Для вычислений могут использоваться отдельные процессы, а библиотеки NumPy и ML сами способны запускать потоки. Часть их операций выполняется вне блокировки интерпретатора Python, GIL, которая ограничивает одновременное выполнение Python-кода потоками в обычной сборке CPython 3.12.

Поэтому четыре процесса сервиса с многопоточной моделью могут создать намного больше вычислительных потоков, чем ожидал автор. В упражнениях этого модуля параллельный код не требуется. К управлению процессами и ресурсами вернёшься при запуске сервиса.
