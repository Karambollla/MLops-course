# Обработка записей

[Практика модуля](../../practice.md) · [Теория](../../README.md) · [Подсказки](../../hints.md) · [SETUP](../../../../SETUP.md)

## Зачем нужна сводка

Представь записи измерений, похожие на события backend-сервиса. Не каждая запись содержит пригодную длительность: поле может отсутствовать, быть строкой или бесконечностью. Если включить его в среднее без проверки, неверное значение испортит весь результат. Эта функция станет вычислительным ядром построчного CLI следующего задания. Правила чисел и различие `None`/нуля разобраны в [главе о записи и результате](../../README.md#от-записи-к-результату).

## Исходное состояние и ход проверки

На входе уже декодированные Python-словари; файлы и JSON здесь читать не нужно. В `solution.py` предоставлена сигнатура, в `test_task.py` — примеры с обычными числами, `bool`, NaN и пустыми полями. Реализуй отбор и агрегацию, сохранив исходные записи. Позже тот же алгоритм должен суммировать поток без обязательного превращения его в список.

Разбери вход `[{"duration": 2}, {"duration": "4"}, {}]`: только первая запись подходит, значит выход `{"count": 1, "mean": 2.0}`. Строку `"4"` нельзя молча преобразовать в число: контракт фильтрует неподходящие типы. После вызова во второй записи по-прежнему должна лежать строка, а пустой словарь должен остаться пустым. Это проверяет и результат, и отсутствие побочного изменения входа; подробности ссылок на объекты — в [разделе об именах и типах](../../README.md#имена-объекты-и-типы).

## Где работать и контракт

Редактируй `modules/00-python/tasks/01-records/solution.py`. Дополнительные тесты размещай в этой же папке.

`summarize(records: list[dict]) -> dict` принимает список словарей, учитывает только конечные положительные int/float duration, исключает bool; возвращает count и mean (None для пустой выборки). Не изменяет вход.

Базовая среда из SETUP: Python, pytest; CPU, Linux/macOS.

Тесты функций работают offline на маленьких входах и временных файлах. До реализации ожидается `NotImplementedError`; ошибка импорта означает проблему подготовки среды. Проверка функций не заменяет описанный опыт на данных или стенде.

Это задание использует функции; импортируй заготовку через `course_tasks.load_task("00-python/01-records")` из Python. CLI не требуется.

## Требования практического опыта

Реализуй `summarize(records)` со следующим контрактом: принимает список словарей, учитывает только конечные положительные значения `duration` типа `int` или `float`, исключая `bool`. Возвращает `{"count": N, "mean": value}`; для пустой выборки среднее равно `None`. Вход не изменяется.

```bash
make task TASK=00-python/01-records
```

До реализации ожидается ошибка `NotImplementedError`; после — зелёные тесты. Добавь проверки NaN, бесконечности и отсутствия мутации. Результат проверяется кодом и тестами фильтрации `bool`/`int`.

## Приёмка и очистка

Запусти указанную выше команду `make task` после реализации и исправления ошибок. Проверяемые случаи перечислены в соседнем `test_task.py`.

Docker не требуется. Временные тестовые файлы убирает pytest; окружение можно завершить `deactivate`. Для табличной темы сохрани CSV и вычисленную сводку, данные понадобятся в модуле ML.

## Пример корректного результата

Для Python-входа `[{"duration": 2}, {"duration": 4}, {"duration": True}]` функция возвращает `{"count": 2, "mean": 3.0}`. Для пустого ввода — `{"count": 0, "mean": None}`. При выводе в JSON `None` превратится в `null`.
