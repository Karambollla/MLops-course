## Где работать и контракт

Редактируй `modules/00-python/tasks/03-tabular-analysis/solution.py` (физическая заготовка рядом). Дополнительные свои тесты и `report.md` размещай в этой же папке. Полных решений в заготовке нет.

`describe_frame(frame) -> dict` возвращает shape как список [rows, cols], dtypes и missing по всем столбцам, quantiles {column: {"0.25": value, "0.5": value, "0.75": value}} для числовых столбцов (pandas linear interpolation). `align_series(left, right) -> tuple` выравнивает Series по общим меткам через inner join с сохранением порядка левой Series; не сбрасывает индекс по позиции. `write_report(csv_path: Path, output: Path) -> None` пишет Markdown shape/dtypes/missing/quantiles. Target описывается, но никогда не передаётся как признак. Покажи ошибочное и исправленное сложение Series в report.md.

## Среда и зависимости

Базовая среда, pandas; CPU.

Данные: python -m housing.data --output work/housing.csv. Вызови write_report для work/python-summary.md из Python. Зависит от загрузки данных; Docker не нужен.

## Запуск и результат

Из корня репозитория:

```bash
make task TASK=00-python/03-tabular-analysis
```

До реализации ожидается RED: `NotImplementedError`, а не ошибка импорта зависимостей. После реализации все offline-тесты должны быть зелёными. Они создают временные данные через pytest tmp_path; полный housing автоматически не скачивается.

Это задание использует функции; импортируй заготовку через `course_tasks.load_task("00-python/03-tabular-analysis")` из Python. CLI не требуется.

## Требования практического опыта

После скачивания housing.csv выведи shape, dtype, число пропусков и квантили каждого столбца. Сохрани вывод в `work/python-summary.md`. Покажи пример расхождения индексов двух Series и исправь его. Не используй target в качестве признака.

## Приёмка и очистка

Пройди все тесты `test_task.py`, сохрани перечисленные артефакты и добавь объяснение решений/ограничений в `report.md`. Для инфраструктурных опытов приложи реальные команды и вывод: offline проверки не доказывают развёртывание, доступность удалённого сервера или качество объяснения. Ручная оценка: воспроизводимость шагов, соответствие исходному контракту, объяснение причины сбоя и корректное восстановление.
