# JSONL и ошибки

[Практика модуля](../../practice.md) · [Теория](../../README.md) · [Подсказки](../../hints.md) · [SETUP](../../../../SETUP.md)

## Где работать и контракт

Редактируй `modules/00-python/tasks/02-jsonl-cli/solution.py` (физическая заготовка рядом). Дополнительные тесты размещай в этой же папке. Полных решений в заготовке нет.

`iter_records(stream: Iterable[str]) -> Iterator[dict]` читает по одной строке, выдаёт JSON objects; повреждённый JSON или не-object вызывает ValueError с номером строки (с 1). Пустая строка тоже ошибка. `summarize_file(path: Path) -> dict` использует summarize из 01-records без накопления всего файла (передай генератор, при необходимости расширь summarize до Iterable). `main()` CLI: позиционный path, JSON результата в stdout, ошибка в stderr и ненулевой exit. Неверный duration отфильтровывается, а не считается повреждённым JSON.

## Среда и зависимости

Базовая среда из SETUP: Python, pytest; CPU, Linux/macOS.

Зависит от 00-python/01-records. Файлы fixtures/valid.jsonl и broken.jsonl содержат три строки.

## Запуск и результат

Из корня репозитория:

```bash
make task TASK=00-python/02-jsonl-cli
```

До реализации ожидается RED: `NotImplementedError`, а не ошибка импорта зависимостей. После реализации все offline-тесты должны быть зелёными. Они создают временные данные через pytest tmp_path; полный housing автоматически не скачивается.

CLI из корня (пути аргументов относительно текущей директории; для JSONL передай полный путь к fixture):

```bash
python scripts/run_task.py run 00-python/02-jsonl-cli -- modules/00-python/tasks/02-jsonl-cli/fixtures/valid.jsonl
```

## Требования практического опыта

Добавь отдельный CLI, который читает JSONL построчно и использует функцию из задания 1. Повреждённая JSON-строка должна завершать CLI с ненулевым кодом и номером строки; неверное поле `duration` обрабатывается по контракту функции. Сравни поведение файла из трёх корректных строк и файла с повреждённой второй строкой. Не загружай весь файл в память.

## Приёмка и очистка

Выполни `test_task.py`: проверяются результаты функций, ошибки входа и изменения технических артефактов. Письменный пересказ выполнения не требуется.

Docker не требуется. Временные тестовые файлы убирает pytest. Сохрани необходимые CSV, split и модель для следующих модулей; окружение можно завершить `deactivate`. Учебные DVC demo/remote удаляй только после экспорта результатов.

## Пример корректного результата

Для fixtures/valid.jsonl CLI печатает JSON `{"count": 2, "mean": 3.0}` и завершается с кодом 0. Для broken.jsonl — ненулевой код, сообщение о строке 2 в stderr, без успешной JSON-сводки в stdout.
