# Критерии оценки проекта

Оценка по доказательствам, а не по числу контейнеров. Каждый пункт оценивается 0 — отсутствует, 1 — частично/ручные шаги, 2 — воспроизводимо и объяснено.

| Область | Что проверить |
|---|---|
| Данные | Источник, схема, SHA-256, восстанавливаемая версия |
| Оценка | Baseline, корректный split, MAE/RMSE и ограничения |
| Артефакт | Pipeline, feature order, версии, release linkage |
| API | Позитивный путь, 422, 503 и parity |
| Оркестрация | Реальные шаги, retries, отсутствие дубликатов |
| Поставка | Проверенный image, Helm values и точная версия |
| Восстановление | Реальный rollback с проверкой прогнозов |
| Мониторинг | Метрики, alert и два разных сценария отказа |
| Документация | Повторение с чистого окружения и cleanup |
| Объяснение | Компромиссы, ресурсы, границы знания |

Ориентир завершения: не меньше 16/20 и ни одного нуля в данных, оценке, API и восстановлении. Это внутренняя учебная рубрика, не прогноз найма. Search/GPU расширения оцениваются отдельно и не компенсируют утечку данных или неработающий основной сервис.

Перед защитой выбери три решения, которые изменишь при росте числа команд, и два компонента, которые удалишь в упрощённой системе. Подкрепи каждый выбор конкретным требованием.
