# Технические проверки проекта

Балльной оценки и обязательного письменного отчёта нет. Проверяй поведение системы командами из README своей реализации.

| Область | Проверка | Корректный результат |
|---|---|---|
| Данные | Восстановить версию CSV, сравнить SHA-256 | Совпадает с manifest |
| Модель | Повторить split, baseline и candidate evaluation | Нет пересечений, preprocessing fit только на train, candidate проходит порог |
| Артефакт | Загрузить собственный bundle и неверную схему | Правильный bundle работает; несовместимый отклоняется до predict |
| API | Запросы с моделью, без неё, с неверными признаками | 200/503/422; HTTP-прогнозы совпадают с Pipeline |
| Оркестрация | Повторить один run_key и прервать publish | Нет второй публикации, отказ не маскируется success |
| Выкладка | Развернуть v1, обновить v2 и откатить | Готовый Service, точная версия модели; rollback возвращает прогноз v1 |
| Мониторинг | Остановить API, затем восстановить | Target down и alert firing, затем восстановление и снятие alert |
| Воспроизводимость | Пройти README с чистого окружения | Данные, обучение, запуск и остановка повторяются без устных инструкций |

Например, без модели `/live` возвращает 200, а `/ready` и валидный `/predict` — 503. После загрузки модели readiness становится 200; неверный batch остаётся 422. Отсутствие исключений само по себе не заменяет проверку результата.

Конкретные имена ресурсов и версии берутся из твоей реализации. Search и GPU-serving проверяются отдельно на совместимом оборудовании; их отсутствие не подменяется заранее заполненной таблицей. [Рекомендации для интервью](../../modules/17-career/practice.md) необязательны.
