# Расширение: поиск по технической документации

[Курс](../../README.md) · [Qdrant](../../modules/13-qdrant/README.md) · [Сравнение движков](../../modules/14-elasticsearch-opensearch/README.md)

## Задача

Пользователь описывает симптом или задачу и получает релевантные инструкции из документации твоего ML-проекта. Примеры: «модель после выкладки не готова», «вернуть прежнюю версию», «повторить обучение без дубликатов». Источник — собственные README, runbooks и заметки; внешнюю документацию массово не копируй.

## Минимальная версия

1. Подготовь минимум 30 небольших документов с устойчивыми IDs, title, text и topic.
2. Зафиксируй корпус по SHA-256. Разметь минимум 20 queries с relevant IDs до просмотра новой выдачи.
3. Сделай lexical baseline и CPU embeddings; фиксируй model ID, revision, размерность и preprocessing.
4. Создай Qdrant collection с явной distance, загрузи points, проверь upsert и фильтрацию.
5. Добавь endpoint `/search` в отдельный поисковый сервис: query, limit 1–10, необязательный topic; ответ — IDs, title, score, source path и index version.
6. Измерь Recall@5, MRR, latency и ошибки на одинаковых queries.

Не добавляй `/search` в основной housing API до завершения его приёмки. У поискового сервиса отдельные зависимости и независимый failure domain.

## Версия индекса и восстановление

Manifest индекса связывает corpus hash, embedding model revision, chunking, dimension, distance и collection. Для нового embedding создавай новую коллекцию. После проверки переключай alias; старую коллекцию сохраняй до проверки rollback. Backup без исходного корпуса и preprocessing неполон.

Проверь три сбоя: неизвестная коллекция, неверная размерность query vector и недоступный Qdrant. API должен отличать 4xx входа от 5xx зависимости и ограничивать время ожидания. Не возвращай пустую выдачу как будто это успешный поиск при отказе БД.

## Сравнение альтернатив

Повтори тот же корпус и embeddings в Elasticsearch и OpenSearch по отдельности. Примени client-side RRF c=60. Сравни качество и сопровождение: mapping, filters, ingest, restart, backup и RAM. На маленьком корпусе нельзя заключать о масштабировании; результаты так и подпиши.

## Необязательный RAG

Только после измеренного retrieval добавь генератор ответа с цитатами на найденные source paths. Публичный платный API не обязателен. Без совместимого локального LLM-стенда подготовь контракт и evaluation cases; не имитируй полноценную генерацию заранее заданным текстом.

Для RAG отдельно оцени retrieval, корректность ссылок, утверждения вне источника, отказ при отсутствии данных и prompt injection в документе. Улучшение текста ответа не доказывает улучшение поиска.

## Приёмка и портфолио

- Corpus и qrels доступны в собственной реализации; разметка не подогнана под один движок.
- Есть per-query evaluation, baseline и index manifest.
- Повторный ingest не дублирует документы, отказ БД виден как отказ.
- Изменение index version и rollback проверены.
- Числа в README сопровождаются hardware, версиями и параметрами нагрузки.

Начальные файлы `labs/search/corpus.json` и `queries.json` содержат восемь документов и ручные векторы: это проверка интерфейсов, а не готовый портфолио-проект.
