# Проверки курса

Здесь перечислены проверенные сценарии, платформы и границы проверки. Они относятся к инфраструктуре и учебным контрактам; собственную реализацию заданий проверяй отдельно.

## Материалы и Python

| Проверка | Подтверждённый результат | Граница |
|---|---|---|
| Структура курса | 18 модулей, 42 технических задания и 11 руководств; внутренние ссылки, UTF-8, блоки кода, Python AST и JSON | Не выполняет учебные функции |
| Markdownlint | Оформление Markdown проходит проверку | Не оценивает содержание объяснений |
| Готовый код | Проверены загрузчик заданий, runner, экспорт артефактов и готовая HTTP-обвязка | Зелёный общий CI не означает выполнение практики |
| Учебные тесты | Собираются без установки всего дополнительного стека | Незавершённые функции дают NotImplementedError; интеграция без включения пропускается |
| Необязательные SDK | Импорты находятся на уровне модулей; отсутствие MLflow, ClearML, PyYAML или ONNX Runtime не мешает сбору базовых тестов | Реальный запуск соответствующего задания требует установки его зависимостей |
| ClearML SDK | Offline-пример с вычисленным MAE и файлом артефакта; захват CLI-параметров data/output/seed; закрытие Task при ошибке обучения | Проверка SDK 1.18.0 не включает Server, очередь и исполнение Agent |
| Примеры теории | Выполнены небольшие примеры pandas, sklearn, хеширования, сериализации и валидации; MLflow SDK по HTTP; импорт toy DAG и проверка суточного timetable Airflow 3.1.0 | Использованы временные данные и отдельный MLflow server; работа полного учебного DAG через scheduler не проверяется этим примером |
| API | Проверены 200/422/503, NaN/Infinity, порядок признаков, parity с Pipeline и отказ на несовместимый bundle | В тестах используются временные синтетические модели |
| Экспорт файлов | Проверены полный комплект, JSON, конфликты, --replace, повтор без изменений и запуск из другой директории | Качество модели не проверяется копированием файлов |
| Зависимости | Основной lock устанавливается с Python 3.12; дополнительные окружения разрешаются отдельно | Разрешение зависимостей не доказывает запуск сервиса или GPU-модели |
| California Housing | Загрузка CSV, схема 20640 × 9 и вычисление SHA-256 | Не является обучением модели учащегося |

Python-проверки выполнены на macOS ARM64 с CPython 3.12.12. Нативные CPU-проверки включают экспорт синтетического Pipeline в ONNX с численным сравнением и Qdrant in-memory: upsert без дубликатов, фильтрацию и метрики на учебных векторах.

## Стенды

Контейнерные проверки выполнены на Linux ARM64. Для Kubernetes использованы kind 0.27.0, Kubernetes 1.32.2 и Helm 3.17.3. Точные версии остальных компонентов — в [матрице совместимости](versions.md).

| Стенд | Проверенные сценарии |
|---|---|
| Housing | Сборка; готовность с моделью и без неё; запросы predict; валидация входа; non-root UID; read-only mount; перезапуск |
| MLflow | Tracking по HTTP; запись и чтение артефактов; регистрация модели с signature; alias; pyfunc predict; сохранность данных после restart |
| Airflow | Сборка; отдельный ML venv; UI; импорт DAG; unpause/trigger; validate_data; сохранение истории после restart |
| Prometheus/Grafana | Scrape; datasource и dashboard; счётчик запросов; firing при остановке API и снятие alert при восстановлении |
| Vault | KV v2; ограниченная policy; разрешённое чтение; отказ на чужой путь и запись; истечение token |
| Ansible | Linux-контейнер; syntax-check; применение конфигурации; повторный запуск с changed=0; сохранение результата в bind mount |
| Qdrant | Upsert со стабильными IDs; фильтрация; ошибка размерности; snapshot; сохранность коллекции после restart |
| Elasticsearch/OpenSearch | Раздельные стенды; mapping; bulk без ошибок отдельных документов; keyword/vector search; сохранность после restart |
| Terraform | Init/validate; apply; HTTP endpoint; повторный plan без изменений; обнаружение удаления; восстановление и destroy |
| Kubernetes/Helm | Running без readiness при отсутствии модели; рабочий Service; ошибка image; Deployment rollback; Helm install/upgrade/rollback; восстановление после неудачного atomic upgrade |

Compose-конфигурации проходят config-проверку. Настоящие Docker/HTTP-тесты задания контейнера проверены как с временной моделью, так и с пустым каталогом моделей. Другие интеграционные pytest-проверки требуют отдельного запуска на подготовленном стенде; перечисление сценариев не означает, что каждый тестовый файл выполнялся в реальном окружении.

## Границы

- Для проверки инфраструктуры использованы синтетические sklearn-модели и маленький учебный поисковый корпус. Их результаты не являются метриками качества California Housing или настоящих semantic embeddings.
- Обучение, quality gate и publish в Airflow остаются упражнениями. Достижение NotImplementedError подтверждает вызов заготовки, но не успешное обучение.
- Дополнительные ClearML Server/Agent и Triton для Linux x86_64 не запускались через эмуляцию ARM64. Локальная ONNX-проверка не заменяет серверный инференс.
- TensorRT-LLM, vLLM и SGLang не запускались на NVIDIA GPU. GPU TTFT, tokens/s и VRAM-сравнения не подтверждены.
- Удалённый GitHub Actions не проверен. Локальные команды workflow доступны ниже.
- HTTP-статус источника и наличие image tag не гарантируют доступность в будущем или совместимость с конкретным оборудованием. Проверка alert не подтверждает доставку внешнего уведомления.

## Как повторить

После [подготовки окружения](../SETUP.md), из корня:

```bash
make check
make test
make tasks-collect
npm exec --yes --package markdownlint-cli2@0.18.1 -- markdownlint-cli2 '**/*.md'
```

Конкретное задание проверяется отдельно:

```bash
make task TASK=00-python/02-jsonl-cli
```

До реализации функции ошибка ожидаема. Для подготовленного контейнерного стенда используй параметры из README задания:

```bash
MLOPS_RUN_INTEGRATION=1 MLOPS_CONTAINER_ID=CONTAINER_ID make task TASK=03-service-ci/02-container
```

Интеграционные тесты не разворачивают и не удаляют инфраструктуру. Разные задания могут требовать разных состояний стенда, поэтому включай их по одному. Для Kubernetes нужен явно заданный контекст.

Внешние ссылки проверяются командой `make links`. Для Compose без запуска: `docker compose -f ПУТЬ config --quiet`. Остальные команды запуска и остановки приведены в соответствующих заданиях.
