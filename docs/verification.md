# Проверки курса

Здесь перечислены проверенные сценарии, платформы и границы проверки. Они относятся к инфраструктуре и учебным контрактам; собственную реализацию заданий проверяй отдельно.

## Материалы и Python

| Проверка | Подтверждённый результат | Граница |
|---|---|---|
| Структура курса | 18 модулей, 39 отдельных технических заданий, 11 руководств и ML-notebook с тремя разделами; внутренние ссылки, UTF-8, блоки кода, Python AST и JSON | Не выполняет учебные функции; структуру и проверки ML-notebook проверяй отдельно |
| Markdownlint | Оформление Markdown проходит проверку | Не оценивает содержание объяснений |
| Готовый код | Проверены загрузчик заданий, runner, экспорт артефактов, готовая HTTP-обвязка и stdlib runtime Airflow | Зелёный общий CI не означает выполнение практики |
| Учебные тесты | Собираются без установки всего дополнительного стека; проверяют расчёты, ошибки входа, CLI, файлы и взаимодействие с SDK | Незавершённые функции дают NotImplementedError; интеграция и SDK без включения пропускаются |

| Примеры теории | Выполнены небольшие примеры pandas, sklearn, хеширования, сериализации и валидации; MLflow SDK по HTTP; исполнение отдельного TaskFlow DAG в Airflow 3.1.0, XCom, суточный контекст и retry после записи файла | Использованы временные данные и отдельный MLflow server; работа полного учебного DAG через scheduler не проверяется этим примером |
| API | Проверены 200/422/503, NaN/Infinity, порядок признаков, parity с Pipeline и отказ на несовместимый bundle | В тестах используются временные синтетические модели |

| Зависимости | Основной lock устанавливается с Python 3.12; дополнительные окружения разрешаются отдельно | Разрешение зависимостей не доказывает запуск сервиса или GPU-модели |
| California Housing | Загрузка CSV, схема 20640 × 9 и вычисление SHA-256 | Не является обучением модели учащегося |

Python-проверки выполнены на macOS ARM64 с CPython 3.12.12. Нативные CPU-проверки включают экспорт синтетического Pipeline в ONNX с численным сравнением и Qdrant in-memory: upsert без дубликатов, фильтрацию и метрики на учебных векторах.

## ML-notebook

В `01-ml` учебные проверки находятся только внутри [housing.ipynb](../modules/01-ml/housing.ipynb). `make check` проверяет наличие notebook, а `make test`, `make tasks` и `make tasks-collect` не подтверждают выполнение его заданий. Проверочные ячейки запускаются учащимся в текущем ядре; незавершённые определения дают `NotImplementedError`.

`housing.train` и `housing.evaluate` загружают только ячейки `course:imports` и `course:definitions` из сохранённого файла. Тесты инфраструктуры импорта используют временные demo-notebook: проверяют отбор ячеек, свежесть определений, ошибки формата, синтаксиса и ограничения пути. Они не проверяют решение ML-упражнений.

Проверены установка зависимостей первой ячейкой в отдельном ядре Python 3.12, отображение таблицы и графика на синтетическом CSV, формат notebook и якоря оглавления. Все восемь учебных проверочных ячеек доходят до `NotImplementedError`; последующие зависимые ячейки без реализации могут давать `NameError`. Полное обучение учащегося и качество California Housing этим не подтверждены.

Сохранение проверено отдельно на временном комплекте: четыре файла, повтор без изменений, отказ при конфликте, явная замена, сохранность посторонних файлов и отказ при NaN в JSON. Оба образа housing/Airflow собираются и импортируют определения без Jupyter, сети и запуска обучения.

## Границы

- Для проверки инфраструктуры использованы синтетические sklearn-модели и маленький учебный поисковый корпус. Их результаты не являются метриками качества California Housing или настоящих semantic embeddings.
- Фабрика DAG и задачи gate/publish/prepare_interval остаются упражнениями. Восемь включённых SDK-проверок останавливаются на `NotImplementedError` фабрики. Успешный отдельный SDK-пример не подтверждает выполнение учебного графа или обучения.
- Дополнительные ClearML Server/Agent и Triton для Linux x86_64 не запускались через эмуляцию ARM64. Локальная ONNX-проверка не заменяет серверный инференс.
- TensorRT-LLM, vLLM и SGLang не запускались на NVIDIA GPU. GPU TTFT, tokens/s и VRAM-сравнения не подтверждены.
- Удалённый GitHub Actions не проверен. Локальные команды workflow доступны ниже.
- HTTP-статус источника и наличие image tag не гарантируют доступность в будущем или совместимость с конкретным оборудованием. Проверка alert не подтверждает доставку внешнего уведомления.

## Как повторить

После [подготовки окружения](../SETUP.md), из корня:

```bash
make check
make test
make tasks-collect
npm exec --yes --package markdownlint-cli2@0.18.1 -- markdownlint-cli2 '**/*.md'
```

Конкретное задание проверяется отдельно:

```bash
make task TASK=00-python/02-jsonl-cli
```

До реализации функции ошибка ожидаема. Для подготовленного контейнерного стенда используй параметры из README задания:

```bash
MLOPS_RUN_INTEGRATION=1 MLOPS_CONTAINER_ID=CONTAINER_ID make task TASK=03-service-ci/02-container
```

Интеграционные тесты не разворачивают и не удаляют инфраструктуру. Разные задания могут требовать разных состояний стенда, поэтому включай их по одному. Для Kubernetes нужен явно заданный контекст.

Внешние ссылки проверяются командой `make links`. Для Compose без запуска: `docker compose -f ПУТЬ config --quiet`. Остальные команды запуска и остановки приведены в соответствующих заданиях.

Локальные SDK-проверки MLflow/Qdrant/ONNX/Vault/Triton и записывающие проверки поисковых сервисов/Vault/MLflow собираются и достигают ожидаемых NotImplementedError учебных функций. Это не зелёная приёмка решений. Настоящие SDK установлены в отдельных окружениях; обычные тесты курса по-прежнему собираются без них.

Тесты с marker `writes` дополнительно требуют `MLOPS_RUN_WRITES=1` вместе с `MLOPS_RUN_INTEGRATION=1`. Они создают только собственные уникальные ресурсы. Поисковые и другие сервисные тесты очищают свои ресурсы. Airflow сохраняет собственные runs и каталоги `work/airflow-acceptance-*` для сопоставления с XCom и логами. Probes чтения используют один integration-флаг. Airflow writes-тесты отдельно проверяют scheduler retry и сохранность интервала, read-only наблюдатели читают выбранные подготовленные runs.

### Исключённые LLM API

Не выполняются и не имитируются generation/streaming/benchmark endpoints vLLM/SGLang (`16-llm-serving/02-engines`), генерация TensorRT-LLM и его Triton backend (`16-llm-serving/03-tensorrt`), а также необязательный генератор ответа RAG-проекта. API-клиенты этих сценариев не добавлены. Локальные формулы памяти, SSE-парсинг и TTFT/TPOT по подготовленным событиям сохранены; они не считаются интеграцией с языковой моделью.
