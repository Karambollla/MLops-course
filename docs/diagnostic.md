# Диагностика перед стартом

Без поиска ответь и выполни небольшие задания. Оценка каждого пункта: 0 — не знаю, 1 — объясняю, 2 — выполняю и проверяю. Это карта пробелов, а не экзамен на поступление.

| Область | Проверка |
|---|---|
| Python | Прочитать JSONL, отфильтровать записи, обработать ошибку формата |
| Тесты | Проверить пустой ввод, неверный тип и корректный результат |
| Linux | Найти процесс на порту, прочитать лог, объяснить SIGTERM |
| Docker | Объяснить разницу image/container/volume и host/container port |
| Сети | Объяснить, почему localhost внутри контейнера не указывает на ноутбук |
| CI | Разделить проверку pull request и публикацию артефакта |
| ML | Объяснить train/validation/test, leakage и baseline |
| Метрики | Выбрать MAE или RMSE для регрессии и объяснить отличие |
| Kubernetes | Отличить Pod, Deployment и Service; найти причину Pending |
| Эксплуатация | Разделить здоровье HTTP-сервиса и качество модели |

Если по Python или ML меньше 4 из 6 баллов в связанных пунктах, не сокращай дни 1–2. Если Docker и сети вызывают трудности, выполни вводный Docker workshop из каталога источников до дня 3. Kubernetes изучается с нуля в модуле 07.

Первый артефакт: `work/diagnostic.md` с баллами, примерами и выбранными пробелами. Повтори диагностику после проекта: укажи доказательства вместо субъективного «теперь понимаю».
