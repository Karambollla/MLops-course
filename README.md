# Из Go backend в MLOps

Практический курс для Go-разработчика, который знаком с основами ML и хочет научиться сопровождать модели: от воспроизводимого обучения до мониторинга и отката. Объяснения на русском, первоисточники преимущественно на английском. Версия материалов: **31 октября 2026 года**.

## С чего начать

1. Пройди [диагностику](docs/diagnostic.md) и подготовь [окружение](SETUP.md).
2. Выбери [интенсив на 14 дней или маршрут на 7 дней](ROADMAP.md).
3. Открой [первый модуль](modules/00-python/README.md). После теории переходи к `practice.md`, затем при необходимости к `hints.md`.
4. Сохраняй доказательства выполнения в `work/`: метрики, конфигурации, команды и выводы. Отмечай [прогресс](PROGRESS.md).
5. Развивай [основной проект](projects/capstone/README.md), а после него — [поисковое расширение](projects/search/README.md).

За 14 дней по 6–8 часов можно пройти основной ML-цикл и собрать первый проект. Полное освоение всего стека потребует продолжения: лабораторные вводных блоков не нужно втискивать в последние часы дня. Готовность к работе определяется самостоятельными решениями и объяснением компромиссов.

## Как устроена практика

В `labs/` лежат стартовые файлы. `TODO(student)` и `NotImplementedError` обозначают твою часть работы. При этом конфигурации стендов и базовые служебные endpoints готовы. Проверки учебной логики сначала пропускаются с явным объяснением; включи их флагом `RUN_EXERCISES=1`, чтобы получить ожидаемые падения до реализации.

Основной проект — Python-сервис прогноза стоимости жилья на California Housing. Его расширение — поиск по собственной технической документации. Go можно добавить как gateway после завершения основного маршрута; обязательную ML-часть выполняй на Python.

## Платформы и проверки

- Основной маршрут: CPU, macOS ARM64, 16 ГБ RAM, локальные сервисы без обязательной регистрации.
- Airflow, ClearML и поисковые движки запускаются по отдельности. Таблица ресурсов и ограничения — в [SETUP](SETUP.md).
- Triton в закреплённом образе и NVIDIA LLM-лабораторные требуют другой среды. Для Mac есть отдельные задания по экспорту, контрактам и анализу; они не считаются GPU-опытом.
- `make check` проверяет целостность материалов без Docker. `make test` запускает тесты стартового проекта после установки зависимостей. Проверка запуска стендов выполняется отдельно.
- Фактически выполненные проверки и ограничения среды записаны в [отчёте](docs/verification.md). Наличие конфигурации не означает, что её запуск проверен.
