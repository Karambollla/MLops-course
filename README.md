# Из Go backend в MLOps

Практический курс для Go-разработчика, который знаком с основами ML и хочет научиться сопровождать модели: от воспроизводимого обучения до мониторинга и отката. Объяснения на русском, первоисточники преимущественно на английском.

## С чего начать

1. Подготовь [окружение](SETUP.md).
2. Посмотри [программу и порядок прохождения модулей](ROADMAP.md).
3. Открой [первый модуль](modules/00-python/README.md). В README каждого модуля собраны теория, подготовка и список заданий. Из списка переходи к README нужной темы: там описаны аргументы, результат, команды проверки и завершение работы.
4. Сохраняй результаты практики в `work/`: метрики, конфигурации, команды и выводы.
5. Развивай [основной проект](projects/capstone/README.md), а после него — [поисковое расширение](projects/search/README.md).

## Как устроена практика

Курс содержит **39 отдельных технических заданий, 11 руководств с примерами и ML-notebook с тремя разделами практики**. У отдельной темы есть собственная папка. Для задания с кодом она выглядит так:

```text
modules/00-python/tasks/02-jsonl-cli/
├── README.md
├── solution.py
├── test_task.py
└── fixtures/
```

Открой README темы: там указаны входы, результат и проверка. Технические задания содержат код или конфигурацию и тесты поведения. Руководства дают команды и примеры корректного результата. Для них нет обязательной письменной сдачи и тестов заполненности.

В [ML-notebook](modules/01-ml/housing.ipynb) находятся все три задания модуля 01 и их проверки. Последняя ячейка сохраняет модель и метаданные прямо в `work/artifacts/`. В остальных заданиях результаты обычно сохраняются в `output/`. Для ONNX есть готовый `export.py`. Подробнее — [результаты и перенос](docs/task-structure.md#результаты-и-перенос).

```bash
make task-list
make task TASK=00-python/01-records
make task TASK=00-python/02-jsonl-cli
make task TASK=00-python/03-tabular-analysis
```

`NotImplementedError` означает незавершённую учебную функцию. `make test` проверяет готовые компоненты курса. `make tasks-collect` собирает учебные тесты. `make tasks` запускает проверки технических заданий. Интеграционные тесты без флага пропускаются. Для проверки конкретного подготовленного стенда используй `MLOPS_RUN_INTEGRATION=1 make task TASK=...` и параметры из README: разные задания могут требовать разного состояния стенда. Пропуск не подтверждает выполнение практики. Для руководства runner покажет путь к материалу. Проверки `01-ml` запускаются только внутри notebook. Общие команды их пропускают.

В `labs/` размещены общий пакет проекта, точки запуска CLI и конфигурации стендов. Реализации упражнений редактируются в tasks или, для `01-ml`, в notebook. Адаптеры общего проекта обращаются к этим источникам. [Подробности структуры](docs/task-structure.md) · [Практика инструментов по всем темам](docs/practice-map.md).

Основной проект — Python-сервис прогноза стоимости жилья на California Housing. Его расширение — поиск по собственной технической документации. Go можно добавить как gateway после завершения основного проекта. Обязательную ML-часть выполняй на Python.

## Платформы и проверки

- Основные задания выполняются на локальном CPU, сервисы не требуют обязательной регистрации. Совместимость с ARM64 и бюджет памяти для отдельных стендов описаны в [SETUP](SETUP.md).
- Airflow, ClearML и поисковые движки запускаются по отдельности. Таблица ресурсов и ограничения — в [SETUP](SETUP.md).
- Triton server в закреплённом образе требует совместимой среды. HTTP SDK и ONNX-практика доступны отдельно. В LLM-модуле изучаются архитектура и локальные расчёты. API генерации, streaming и benchmark исключены и не имитируются.
- `make check` проверяет целостность материалов без Docker. `make test` запускает тесты стартового проекта после установки зависимостей. Проверка запуска стендов выполняется отдельно.
- Проверенные сценарии, ограничения и команды собраны в [проверках курса](docs/verification.md). Наличие конфигурации не означает, что её запуск проверен.
